# 世界书

世界书（World Info / Lorebook）是一组按键触发的背景设定条目。聊天时应用扫描最近的消息，命中关键词的条目会被注入提示词，从而在不占用固定人设的前提下按需补充信息。

## 什么是世界书？

每条世界书条目包含关键词、正文与插入位置等属性。发送消息前，`src/lorebook.js` 依据最近对话与当前输入判断哪些条目被激活，`src/chatPipeline.js` 再按位置与顺序把它们拼进 `system` 消息或按深度插入的消息中。

**关键特征**:
- 支持常驻（`constant`）与关键词触发两种激活方式
- 关键词支持普通子串、正则、大小写敏感与全词匹配
- 支持次要关键词（`selective`）与概率（`probability`）
- 支持插入位置与顺序（`position`、`order`、`depth`）
- 扫描范围由 `scanDepth` 控制，缺省为 4 条最近消息

## 记忆摘要条目

记忆总结会把新增记忆写入当前角色世界书：条目名形如 `记忆总结 1`，内容为若干条以 `- ` 开头的记忆行，关键词由 LLM 在输出末行给出（尽量多、覆盖主要事件，无关键词时回退占位 `前情提要`），`constant` 为假、关键词触发、`position` 为 `0`、`order` 为 `10`（值越小越靠前，使记忆排在角色定义之前且靠前位置），可像普通条目一样编辑或删除。生成时会把已有记忆注入提示词的 `<memories>` 区块，要求只提取新增信息，避免重复。发送请求时 `memorySummary` 会把这些条目的内容拼成 `[记忆摘要]` 注入，并截断会话 `summarizedUpTo` 之前的早期消息，实现上下文压缩。

**作用域例外**：世界书对角色全局生效，若同一角色在记忆页存在 ≥ 2 条记忆（会话），写进世界书的总结会造成跨会话串味。此时记忆总结改为写入会话级存储（`@easychat2_session_summaries::<sessionId>`），并只在本会话内作为 `[记忆摘要]` 发送；既有世界书条目保留、只停止新增。判定见 `isSessionScopedMemory`。

## 结构

```javascript
{
  id: 'entry-0',
  comment: '世界书条目 1',      // 显示名，缺省按序号生成
  keys: [],                    // 主关键词
  secondaryKeys: [],           // 次要关键词
  content: '',                 // 注入正文
  constant: false,             // 常驻
  selective: true,             // 启用次要关键词逻辑
  enabled: true,               // 启用
  useRegex: true,              // 关键词按正则解释
  caseSensitive: false,
  matchWholeWords: false,
  position: 0,                 // 0 前 / 1..3,5..7 后 / 4 深度
  positionLabel: '角色定义之前',
  role: 'system',              // 深度插入时的角色（0/1/2 或字符串）
  order: 100,                  // 同位置内排序
  depth: 4,                    // 深度插入的距离
  probability: 100,            // 触发概率
  useProbability: true,
  scanDepth: null              // 扫描最近消息条数，缺省 4
}
```

## 激活规则

按以下顺序判定一条 **已启用** 的条目是否激活：

1. `constant` 为真 → 直接进入概率判定
2. 主关键词为空 → 不激活
3. 取最近 `scanDepth`（缺省 4）条 user/assistant 消息与当前用户输入，拼接为扫描文本
4. 任一主关键词命中（正则或子串，按 `caseSensitive`/`matchWholeWords` 控制）
5. 若 `selective` 为真且 `secondaryKeys` 非空，则任一次要关键词也须命中
6. 概率判定：`useProbability` 为假、或 `probability >= 100` 时必触发；`<= 0` 不触发；否则 `Math.random() * 100 < probability`

激活后的条目按位置分组：

| `position` | 注入方式 |
|-----------|---------|
| `0` | 拼接到 `system` 消息正文之前 |
| `1`、`2`、`3`、`5`、`6`、`7` | 拼接到 `system` 消息正文之后 |
| `4` | 作为独立消息按 `depth` 从末尾插入，角色由 `role` 决定 |

同位置内按 `order` 升序排列；深度插入按目标索引从大到小批量写入，保证相同索引内的顺序稳定。

## 不变量

1. **停用条目绝不激活**: `enabled` 为假直接跳过。
2. **非索引键不参与**: 缺少 `keys` 且非 `constant` 的条目不会激活。
3. **非法正则不致命**: 关键词正则构造失败时视为不匹配，不中断整条发送链路。
4. **深度已夹取**: 插入深度被夹取在 `[1, 消息数 - 1]`，保证插入点在 `system` 之后、末条消息之前。
5. **默认值完备**: 字段缺失时使用标准化默认值，界面与拼装逻辑不依赖原始字段。
