# 正则脚本

正则脚本（Regex Script）是一组对消息文本做查找替换的规则。EasyChat2 在发送前与展示时分别应用相应作用范围的脚本，用于清洗、改写或隐藏特定文本。

## 什么是正则脚本？

每条脚本包含查找正则、替换文本、作用范围与若干开关。`src/regexEngine.js` 的 `applyRegexScripts` 按作用范围（placement）与用途（提示词 / 展示）筛选并顺序执行替换，非法正则被跳过而不影响整条消息。

**关键特征**:
- 作用范围：用户输入、AI 输出、世界信息、推理等
- `promptOnly` 只作用于送模型的提示词，`markdownOnly` 只作用于界面展示，两者皆非则同时生效
- 支持 `minDepth` / `maxDepth` 按消息深度限定
- flags 仅保留 `gimsuy` 并强制包含 `g`，缺省为 `g`

## 代码位置

| 方面 | 位置 |
|------|------|
| 字段标准化与默认值 | `src/cardParser.js` 的 `normalizeRegexScript` |
| 执行引擎 | `src/regexEngine.js` 的 `applyRegexScripts` |
| 发送前应用 | `src/chatPipeline.js` 的 `buildRequestMessages`（mode `prompt`） |
| 展示前应用 | `src/ChatScreen.js` 的 `renderedMessages`（mode `display`）；若替换结果含 HTML 标签，助手消息由 `react-native-render-html` 渲染（渲染前会去掉 ```html 代码围栏，并删除 `<style>` 块；`<script>` 不执行） |
| 界面编辑 | `src/CharacterScreen.js` 的 `RegexEntryEditor`（折叠区块内逐条编辑） |

## 结构

```javascript
{
  id: 'regex-0',
  name: '正则脚本 1',          // 显示名，缺省按序号生成
  findRegex: '',               // 查找正则
  replaceString: '',           // 替换文本；支持 JS 的 $1 / $&，并把 $0 兼容为整段匹配
  flags: 'g',                  // 仅保留 gimsuy，强制含 g
  placement: [1, 2],           // 缺省 [1, 2]
  placementLabel: '用户输入、AI 输出',
  enabled: true,
  markdownOnly: false,         // 仅展示
  promptOnly: false,           // 仅提示词
  minDepth: null,
  maxDepth: null
}
```

## 作用范围

| `placement` | 含义 | 应用点 |
|-------------|------|--------|
| `1` | 用户输入 | 历史用户消息与当前输入在发送前应用；用户气泡展示时也应用展示版本 |
| `2` | AI 输出 | 助手回复（含开场白）在发送历史时按提示词应用，在渲染时按展示应用 |
| `3` | 快捷命令 | 预留，当前无快捷命令入口 |
| `5` | 世界信息 | 命中并拼入系统消息的世界书文本在发送前应用 |
| `6` | 推理 | 预留 |

`placement` 缺省为 `[1, 2]`。`promptOnly` 与 `markdownOnly` 互斥生效：发送提示词时跳过 `markdownOnly`，展示时跳过 `promptOnly`，两者皆非则在两处都执行。

## 不变量

1. **非法正则不致命**: `new RegExp` 抛错时跳过该脚本，继续处理后续脚本。
2. **原始文本落盘**: 助手回复以原始文本持久化，展示与提示词变换在运行时计算，保证变换幂等且历史不被污染。
3. **始终全局替换**: flags 强制包含 `g`，避免 `String.replace` 只替换首个匹配。
4. **深度过滤可选**: `minDepth`/`maxDepth` 为 null 时不做深度限制。
5. **默认值完备**: `placement` 为空或非法时回退 `[1, 2]`。
