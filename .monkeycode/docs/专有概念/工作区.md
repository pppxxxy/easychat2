# 工作区

工作区（Workspace）是让角色**在设备上读写文件**的沙盒协作空间：你在聊天里下指令，助手按当前模式调用工具读取、创建、修改文件，必要时还能执行 shell 命令。

入口：设置 → 工作区 → 打开工作区（`SettingsScreen` 渲染 `src/workspace/WorkspaceChat.js`）。

## 界面结构（主界面）

```
┌────────┬──────────────────────────────┐
│ ＋新建 │ 工作区                   [✕] │  右上角退出
│  对话  │ 查看已创建的文件与历史改动    │  → 文件子面板（WorkspacePanel）
│ ⑂新建  │ ┌──────────────────────────┐ │
│  项目  │ │      聊天消息区           │ │
│ 🕘查找 │ └──────────────────────────┘ │
│  历史  │ ＋ 🎤 [输入框]  ⚙  ➤        │  底部五控件
└────────┴──────────────────────────────┘
```

- **左列**：新建对话 / 新建项目 / 查找历史 / 综合设置，底部 `railSpacer` 是预留位。
- **底部设置按钮（⚙，发送按钮左边）**：八项列表——模型、思考强度、当前工作模式、当前角色、上下文占用显示、导入文件、导出文件、环境配置。前五项就地展开，导入是直接动作，导出 / 文件与改动 / 环境配置交给 `WorkspacePanel` 的子面板（`initialSection`）。
- **综合设置（左列 ⚙）**：界面语言（与「设置 → 外观」同一份存储）、工作模式、帮助与教学。

## 三个模式（门控一切）

| 模式 | 能做什么 |
|------|---------|
| 询问 `ask` | 纯对话，一个文件都不读（无任何工具） |
| 只读 `read` | 可读取并引用工作区内的文本文件 |
| 可改 `write` | 可新建 / 修改文本文件、导出 Word、拉取项目；命令执行开关只在本模式有意义 |

工具按模式门控（`src/agent/tools/registry.js`）。命令执行另有独立开关（默认关），且**每条命令执行前单独弹框确认**；外部 SAF 根下不可用（无 root 权限的 shell 访问不到）。

## 存储键

| 键 | 内容 |
|----|------|
| `@easychat2_workspace` | 设置：`mode`、`location`（根）、`allowCommandExecution`、`assistantCharacterId`、`projects`、`activeProjectId` |
| `@easychat2_workspace_changes` | 文件改动历史（按角色分区，每角色 200 条） |
| `@easychat2_workspace_chats` | **工作区对话**（按角色分区） |

工作区对话与聊天页会话**分开存**：工作区直连 agent 工具循环、不参与角色扮演流水线，混进聊天页列表会把角色聊天淹没。

## 工作区对话（持久化）

- 结构：`{ [characterId]: { activeId, chats: [{ id, title, createdAt, updatedAt, messages }] } }`
- 上限：每角色 40 条会话、每会话 200 条消息、单条消息 20000 字符、角色分区 50 个（`src/workspace/chats.js`）
- 标题：取首条用户指令的第一行（不引 i18n，纯函数里留空、由界面显示「新对话」）
- 落盘时机：**发送时**落 user 消息，**结束 / 失败 / 中止时**一次性落 assistant 终稿；流式期间不写（每帧写会拖垮存储）。按消息 id 去重，重复落盘不产生重复条目。
- 会话与角色在生成开始时**定住**：生成过程中切会话或切角色，落盘仍写回原来那一条。
- 「新建对话」= 另开一条会话（旧会话留在历史里），不是清空上一条。

## 项目（从 GitHub 拉取）

- 走 **zipball** 而不是 `git clone`：设备不保证有 git 二进制，zipball 一个 HTTPS 请求就能拿到某分支快照；解压用内置 `fflate`（纯 JS）。
- 落盘位置：沙盒内 `projects/<owner>__<repo>/`（不占用沙盒根，也避免不同 owner 的同名仓库互相覆盖）。
- 只导入**文本文件**（二进制/媒体/压缩包按 `paths.js` 黑名单跳过），单次上限 400 个文件 / 单文件 512KB。
- 私有仓库需要 `设置 → MCP` 里的 GitHub 令牌；拉取要求**可改模式**。
- **提交与推送不走这里**：仍由聊天里的 GitHub MCP 工具完成（`create_or_update_file` / `push_files`，高危操作逐条确认；`delete_`/`force_`/`admin` 类工具无条件禁止）。
