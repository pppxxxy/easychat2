# 工作区

工作区（Workspace）是让角色**在设备上读写文件**的沙盒协作空间：你在聊天里下指令，助手按当前模式调用工具读取、创建、修改文件，必要时还能执行 shell 命令。

入口：设置 → 工作区 → 打开工作区（`SettingsScreen` 渲染 `src/workspace/screen/WorkspaceScreen.js`——单屏五领域：对话 / 文件 / GitHub / 终端 / 设置）。

## 界面结构（主界面）

```
┌────────┬──────────────────────────────┐
│ ＋新建 │ 工作区                   [✕] │  右上角退出
│  对话  │ 查看已创建的文件与历史改动    │  → 文件领域（WorkspaceScreen）
│ ⑂新建  │ ┌──────────────────────────┐ │
│  项目  │ │      聊天消息区           │ │
│ 🕘查找 │ └──────────────────────────┘ │
│  历史  │ ＋ 🎤 [输入框]  ⚙  ➤        │  底部五控件
└────────┴──────────────────────────────┘
```

- **左列**：新建对话 / 新建项目 / 查找历史 / 综合设置，底部 `railSpacer` 是预留位。
- **底部设置按钮（⚙，发送按钮左边）**：**10 个可展开行**（模型、思考强度、工作模式、当前角色、上下文占用、技能、命令、已记住的授权、钩子、工作区模板）+ **5 个动作行**（导入文件、导出文件、导出会话事件流、文件与改动、环境配置）。
- **综合设置（左列 ⚙）**：界面语言（与「设置 → 外观」同一份存储）、工作模式、帮助与教学。

## 三个模式（门控一切）

| 模式 | 能做什么 |
|------|---------|
| 询问 `ask` | 纯对话，一个文件都不读（无任何工具） |
| 只读 `read` | 可读取并引用工作区内的文本文件 |
| 可改 `write` | 可新建 / 修改文本文件、导出 Word、拉取项目；命令执行开关只在本模式有意义 |

工具按模式门控（`src/agent/tools/registry.js`）。命令执行另有独立开关（默认关），且**每条命令执行前单独弹框确认**；外部 SAF 根下不可用（无 root 权限的 shell 访问不到）。

## 存储键

| 键 | 内容 |
|----|------|
| `@easychat2_workspace` | 设置：`mode`、`location`（根）、`allowCommandExecution`、`allowPythonExecution`、`assistantCharacterId`（**没有** `projects`/`activeProjectId`——那是重构前的旧设计） |
| `@easychat2_workspace_changes` | 文件改动历史（按角色分区，每角色 200 条） |
| `@easychat2_workspace_chats` | **工作区对话**（按角色分区，每角色 40 会话 / 200 消息） |
| `@easychat2_workspace_permissions` | 权限规则（`always` 落盘、`session` 仅内存；三态 `allow` / `ask` / `deny`，优先级 `deny > ask > allow`） |
| `@easychat2_workspace_repo_snapshots` | 每仓库本地副本清单快照（每角色 20 仓库） |

## 权限规则：三个来源（P0-6）

| 来源 | 能产出 | 说明 |
|---|---|---|
| 确认弹框 | `allow`（本次会话 / 永远） | 逐条确认时点「本次会话允许 / 永远允许」；规则只覆盖**用户看到的那条原文**（命令前缀 / 路径），不自动放宽 |
| 设置面板「已记住的授权」→「新增规则」 | `allow` / `ask` / `deny` | 手写工具名 + 匹配内容（命令与代码按前缀、路径按 glob、留空 = 该工具全部调用）。这是写出「必须先问」的入口之一 |
| `.easychat/hooks.json` 的 `before_shell` | `deny`（缺省）/ `ask`（`effect: "ask"`） | 声明式且 agent 可读写，因此**只能收紧不能放宽**：写 `allow` 或拼错一律按 `deny` 处理 |

`ask` 的语义：命中后弹框**只给「拒绝 / 允许这一次」**（没有「本次会话 / 永远允许」），且批准**不记规则**——否则一次点击就把「必须先问」永久解除。与存储里的宽 `allow` 并存时 `ask` 压过 `allow`，这正是「放行 git 但 git push 必须先问」的唯一写法（`deny` 永远最高优先）。

工作区对话与聊天页会话**分开存**：工作区直连 agent 工具循环、不参与角色扮演流水线，混进聊天页列表会把角色聊天淹没。

## 工作区对话（持久化）

- 结构：`{ [characterId]: { activeId, chats: [{ id, title, createdAt, updatedAt, messages }] } }`
- 上限：每角色 40 条会话、每会话 200 条消息、单条消息 20000 字符、角色分区 50 个（`src/workspace/chats.js`）
- 标题：取首条用户指令的第一行（不引 i18n，纯函数里留空、由界面显示「新对话」）
- 落盘时机：**发送时**落 user 消息，**结束 / 失败 / 中止时**一次性落 assistant 终稿；流式期间不写（每帧写会拖垮存储）。按消息 id 去重，重复落盘不产生重复条目。
- 会话与角色在生成开始时**定住**：生成过程中切会话或切角色，落盘仍写回原来那一条。
- 「新建对话」= 另开一条会话（旧会话留在历史里），不是清空上一条。

## 项目（从 GitHub 拉取）

- 走 **zipball** 而不是 `git clone`：设备不保证有 git 二进制，zipball 一个 HTTPS 请求就能拿到某分支快照；解压用内置 `fflate`（纯 JS）。
- 落盘位置：沙盒内 `repos/<owner>/<repo>/<branch>/`（不占用沙盒根；不同 owner 的同名仓库、同一仓库的不同分支互不覆盖）。
- 只导入**文本文件**（二进制/媒体/压缩包按 `paths.js` 黑名单跳过）。限额：zip 包 50MB / 条目 5000 / 解压总量 200MB / 单文件二进制 1MB、文本 5MB；跳过明细写 `.easychat/pull-skipped.json`（上限 1000 条）。
- 私有仓库需要 `设置 → MCP` 里的 GitHub 令牌；拉取要求**可改模式**。
- **推送已内建**（G 系）：`repoPush.js` 批量单提交推送（手写 SHA-1 + git blob sha 判定内容变化，`updateRef` 恒 `force:false`）；推送前写 `.easychat/rollback/<ts>.json` 基线（保留 3 份）供一键回滚；三态 diff 区分「本地新增 / 内容变化 / 远程有而本地未物化（不删）」。`delete_`/`force_`/`admin` 形态的 MCP 工具**跨服务器无条件禁止**（即使用户同意也不解锁）。
- `.easychat/` 下还有：`hooks.json`（声明式钩子）、`env.json`（持久 shell 会话：cwd + 环境变量）、`skills/`、`commands/`、`agents/`、`file-history/`（写前快照，最近 200 条 / 单条 256KB）、`sessions/<id>.jsonl`（会话事件流，512KB 到顶停止）、`repos-manifest/`。**审计与快照的三个目录（sessions / file-history / rollback）不可被 agent 改写**（`paths.js` 的 `assertWritableWorkspacePath`，守卫在工具边界）。
