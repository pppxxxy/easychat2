> 来源：2026-09-29 审核助手 + 用户 + 助理三方讨论共识（用户留存汇总）+ 项目库既有记录。

## 共识约束（全程有效，勿再议）

- 新架构必须开；`ProactiveMessageModule.kt` 的迁移仅在 Interop 验证失败时才做（0c）。
- Interop Layer 优先：旧架构模块走 interop 是官方路径，先验零改动。
- JSC 退路删除：项目用 Hermes，新架构下 JSC 不可行。
- 阶段 4 拆两半：4a（在线 API + 文档生成）可与阶段 2 并行；4b（本地模型降级）死等阶段 2。
- 端侧转写延后（作为离线兜底列入后续阶段）；全双工语音不保留；打电话单列（WebRTC 新架构适配待确认）。
- 内存互斥：同一时刻只允许一个原生重负载能力（本地模型 / 转写 / 其他重负载互斥）。
- 重依赖洁净原则：各阶段只装当前必需依赖，避免 postinstall 网络问题污染编译结论（阶段 0 不装 llama.rn / react-native-webrtc）。
