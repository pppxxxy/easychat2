# 卡解析与提示管线

卡解析与提示管线模块负责把外部角色卡文件解析为应用内角色，并在每次发送前把角色设定、世界书与正则脚本组装为最终请求消息。

## 结构

```
src/
├── cardParser.js       # 角色卡 JSON/PNG 解析、字段与世界书/正则标准化
├── lorebook.js         # 世界书条目激活判定
├── regexEngine.js      # 正则脚本作用范围与提示词/展示应用
├── chatPipeline.js     # 组装 system + 历史 + 用户消息（含世界书与正则）
└── secrets.js          # 共享的密钥脱敏正则与函数
```

## 关键文件

| `src/lorebook.js` | `collectActiveWorldInfo` / `isEntryActive` / `buildWorldInfoText` |

## 依赖

**本模块依赖**:
- `parsecard` - PNG `tEXt` 块主读取
- `buffer` - base64 解码与文本块解析
- `src/lorebook.js`、`src/regexEngine.js` - `chatPipeline` 内部依赖

**依赖本模块的**:
- `src/ChatScreen.js` - 调用 `buildRequestMessages` 与 `applyRegexScripts`
- `src/CharacterScreen.js` - 调用 `parseCardFromPng` / `parseCardFromJson` 与 `maskSecrets`

## 规范

### 解析顺序

1. PNG 先交给 `readJsonFromPNG`；为空或抛错时走本地 `readFallbackJsonFromPng`（仅无压缩 `tEXt`/`iTXt`）
2. 得到 JSON 文本后统一由 `normalizeCard` 处理，PNG 与 JSON 共用同一套字段映射
3. 标准字段按 `data` 优先、顶层兜底，并兼容常见别名
4. 世界书候选位置：`data.character_book`、`root.character_book`、`data/root.worldInfo`、`data/root.world_info`
5. 正则候选位置：`data/root.extensions.regex_scripts`、`data/root.regexScripts`、`data/root.regex_scripts`

### 提示词组装

```javascript
const messages = buildRequestMessages({ character, historyMessages, userText });
// => [ { role:'system', content:'...' }, ...history, { role:'user', content:'...' } ]
```

- 历史中仅保留 `user` / `assistant` 消息
- 历史用户消息与当前输入应用 placement 1 的正则
- 历史助手消息（含开场白）应用 placement 2 的正则
- 命中的世界书文本应用 placement 5 的正则后才拼入系统消息
- 世界书 `position 0` 前插、其余后接、`position 4` 按深度插入
- 系统提示词优先取 `character.systemPromptComposed`，为空回退 `character.systemPrompt`，再回退默认文案
- 角色名为空时不注入「你的名字是…」
- `quote` 非空且文本非空时，在用户消息文本前追加 `[引用<name>的消息] <text>` 强调段（`name` 缺失回退「对方」），只影响当前用户消息；`images` 非空时该文本作为多模态数组的首个 `text` 项
- `groupContext` 非空时追加到 `[记忆摘要]` 之后、插件背景资料之前；单聊不传，行为不变；逐角色群聊由 `src/groupChat.js` 的 `buildGroupContext` 生成，含在场成员名单（简介 + 最近发言）与最近对话
- 群像卡模式不经过 `buildRequestMessages`，而由 `buildEnsemblePrompt` 直接组装「成员设定 + 格式要求」的提示词，要求模型以「角色名：」分段输出，再由 `parseEnsembleReply` 解析为多条消息

### 测试

项目当前无自动化测试框架。上述纯逻辑模块已用 Babel + Node 的临时脚本覆盖 25 项用例（角色卡两种结构、PNG `tEXt`/`iTXt`/无数据、世界书激活、正则作用范围与各 placement、提示词组装、合成提示词优先级、默认条目工厂与 id 去重），改动后需重新运行等价验证。非持久化的纯日志与临时验证脚本不纳入仓库。

## 添加新的角色卡字段

1. 在 `cardParser.js` 的 `extractStandardFields` 增加别名
2. 在 `buildCharacterPatch`（`CharacterScreen.js`）与 `DEFAULT_CHARACTER` 同步字段
3. 如需在界面展示，在 `CharacterScreen.js` 的 `DataField` 区块补充
4. 确认不覆盖已有持久化数据（`updateCharacter` 为浅合并）

**检查清单**:
- [ ] 字段有默认值，缺失不导致渲染报错
- [ ] PNG 与 JSON 两条路径都覆盖
- [ ] 解析错误经 `maskSecrets` 后才展示
- [ ] 不把原始密钥写入存储或日志
