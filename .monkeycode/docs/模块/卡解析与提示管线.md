# 卡解析与提示管线

卡解析与提示管线模块负责把外部角色卡文件解析为应用内角色，并在每次发送前把角色设定、世界书与正则脚本组装为最终请求消息。

### 拆分职责

- `character/cardParser/`：`normalizeUtils` 提供取值工具；`worldInfo`/`regexScripts` 分别负责世界书/正则归一；`standardFields` 抽取标准字段并构造系统提示；`normalizeCard` 汇总整卡；`json` 清洗/解析 JSON；`png` 读取 PNG 文本块。主依赖链为 `png → json → normalizeCard → standardFields/worldInfo/regexScripts → normalizeUtils`。
- `chat/groupChat/`：`constants`/`textUtils` 提供常量与名称/JSON 工具，`profile` 管简介，`scheduler` 管调度，`opening` 管开场；`mediaPrompt` 提供发言者标签与媒体提示，供 `context`（历史/群聊情境/逐角色请求）和 `ensemble`（群像提示/回复解析/合并）共用。
- `cardForge/forge/`：`shared` 提供字段/标签/限额与文本工具，`advanced` 清洗高级条目，`draft` 处理草稿与角色转换，`state` 管问答/记录，`prompts` 构造生成/编辑提示，`patch` 解析模型 JSON 并合并草稿，`assist` 管字段/标签/条目辅助生成。内部依赖为 `state → draft`、`prompts → state/draft`、`patch → advanced/draft`，各层复用 `shared`；`advanced` 仅供内部使用。

## 规范

### 解析顺序

1. PNG 先交给 `readJsonFromPNG`；为空或抛错时走本地 `readFallbackJsonFromPng`（仅无压缩 `tEXt`/`iTXt`）
2. 得到 JSON 文本后统一由 `normalizeCard` 处理，PNG 与 JSON 共用同一套字段映射
3. 标准字段按 `data` 优先、顶层兜底，并兼容常见别名；织语字段 `nickname`、`greeting`、`setting` 映射到名称、开场白、人设/系统提示词
4. JSON 文本先处理 BOM、代码围栏、全角空白与字符串内未转义换行，再交给 `JSON.parse`
5. 世界书候选位置：`data.character_book`、`root.character_book`、`data/root.worldInfo`、`data/root.world_info`、`data/root.worldbook`、`data/root.world_book` 及织语别名
6. 正则候选位置：`data/root.extensions.regex_scripts`、`data/root.regexScripts`、`data/root.regex_scripts`、`data/root.agent_regex`

### 提示词组装

```javascript
const messages = buildRequestMessages({ character, historyMessages, userText });
// => [ { role:'system', content:'...' }, ...history, { role:'user', content:'...' } ]
```

- 历史中仅保留 `user` / `assistant` 消息
- 历史用户消息与当前输入应用 placement 1 的正则
- 历史助手消息（含开场白）应用 placement 2 的正则
- 命中的世界书文本应用 placement 5 的正则后才拼入系统消息
- 世界书 `position 0` 前插、其余后接、`position 4` 按深度插入
- 系统提示词优先取 `character.systemPromptComposed`，为空回退 `character.systemPrompt`，再回退默认文案
- 角色名为空时不注入「你的名字是…」
- `quote` 非空且文本非空时，在用户消息文本前追加 `[引用<name>的消息] <text>` 强调段（`name` 缺失回退「对方」），只影响当前用户消息；`images` 非空时该文本作为多模态数组的首个 `text` 项
- `groupContext` 非空时追加到 `[记忆摘要]` 之后、插件背景资料之前；单聊不传，行为不变；逐角色群聊由 `src/chat/groupChat.js` 的 `buildGroupContext` 生成，含在场成员名单（简介 + 最近发言）与最近对话
- 恒定在系统消息末尾追加 `[输出格式]`（`DEFAULT_OUTPUT_FORMAT_PROMPT`），要求自然分段换行、结构化内容逐行书写；该项不受「全局预设」开关影响，避免回复被挤成一大段
- 群像卡模式不经过 `buildRequestMessages`，而由 `buildEnsemblePrompt` 直接组装「成员设定 + 格式要求」的提示词，要求模型以「角色名：」分段输出，再由 `parseEnsembleReply` 解析为多条消息

### 测试

纯逻辑模块用 `node --test` 覆盖（`tests/` 下 `.test.mjs`，`npm test` 运行），含角色卡两种结构、PNG `tEXt`/`iTXt`/无数据、世界书激活、正则作用范围与各 placement、提示词组装（含常驻输出格式指令）、合成提示词优先级、默认条目工厂与 id 去重等；改动后运行 `npm test` 验证。

## 添加新的角色卡字段

1. 在 `src/character/cardParser/standardFields.js` 的 `extractStandardFields` 增加别名
2. 在 `buildCharacterPatch`（`src/character/cardHelpers.js`）与 `DEFAULT_CHARACTER` 同步字段
3. 如需在界面展示，在 `CharacterDetailScreen.js` 的 `DataField` 区块补充
4. 确认不覆盖已有持久化数据（`updateCharacter` 为浅合并）

- [ ] 字段有默认值，缺失不导致渲染报错
- [ ] PNG 与 JSON 两条路径都覆盖
- [ ] 解析错误经 `maskSecrets` 后才展示
- [ ] 不把原始密钥写入存储或日志
