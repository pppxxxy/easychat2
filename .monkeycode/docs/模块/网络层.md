# 网络层

网络层封装与兼容 OpenAI 协议的大模型接口的通信，负责地址归一、SSE 流式请求、空闲超时与错误格式化；并在其上加一层「在线/本地选择」与厂商请求统一层。

## 结构

```
src/
├── api.js                # sendChatMessage、SSE 解析与相关内部函数
├── fallbackModels.js     # 模型降级链判定层（归一化/可降级判定/链规划，纯函数）
├── vendorHttp.js         # 厂商请求统一层：XHR 封装、SSE 增量解析、超时与取消
├── modelProvider.js      # 在线/本地推理选择与回退（canUseLocalModel / sendWithModelProvider）
├── imageGen/index.js     # generateImage、模型列表/连通性检测、请求构造、响应解析与错误映射
├── imageGen/localDream.js# Local Dream 端侧生图（SSE + 原始 RGB，非 A1111 兼容）
├── vectorMemory/         # embedding 请求、分片、相似度检索与关键词降级
└── localModel/localApiServer.js # 本地 OpenAI 兼容服务（HTTP 在 Kotlin，推理回 JS）
```

**内部函数**:

| 函数 | 目的 |
|------|------|
| `normalizeChatUrl(baseUrl)` | 将根地址、`/v1` 或完整地址统一为 `/chat/completions` 结尾 |

| `extractDeltaContent(payload)` | 从 SSE 事件中取 `choices[0].delta.content`（兼容 `message.content`） |

## 规范

### 代码模式

**基于 XHR 的 SSE 增量读取**:
```javascript
xhr.onprogress = () => {
  const incoming = xhr.responseText.slice(consumed);
  consumed = xhr.responseText.length;
  lineBuffer += incoming;
  const lines = lineBuffer.split('\n');
  lineBuffer = lines.pop() || '';
  lines.forEach(handleLine);
};
```

**空闲超时**:
```javascript
const armIdleTimer = () => {
  if (idleTimer) clearTimeout(idleTimer);
  idleTimer = setTimeout(() => { fail(timeoutError); xhr.abort(); }, 30000);
};
// 每次 onprogress 收到数据后重新 arm
```

**错误归一**:
```javascript
if (xhr.status < 200 || xhr.status >= 300) {
  fail(new Error(formatApiError(xhr.responseText, xhr.status)));
}
```

**取消与中断**:
```javascript
const onAbortSignal = () => { canceled = true; xhr.abort(); };
signal.addEventListener('abort', onAbortSignal);
// settle 时移除监听，避免泄漏
xhr.onabort = () => fail(canceled ? createAbortError() : new Error('请求已中断。'));
```

### 模型降级链（P0-7）

配置 `apiConfigs[].fallbackModels`（最多 3 个模型名，逗号/空格/换行分隔，存储层 `normalizeFallbackModels` 归一）后，`streamChatCompletion` 按 `planFallbackChain` 依次尝试：主模型在前，同名降级项不重复试。

- **接线点在 `streamChatCompletion`**：它是所有在线请求的唯一收口（聊天走 `agent/loop.js`，群聊/记忆总结/压缩/日记/动态/制卡各自直连），逐处加壳必漏。单次 XHR 往返抽成内部函数 `requestOnce(messages, options, { config, model, protocol, url, thinkingSettings, samplingSettings, … })`，外层只负责「按链循环 + 判定该不该换」。
- **可降级失败**（`fallbackModels.js` 的 `isRetryableFailure`）：429、5xx、超时（`error.timeout`）、网络不可达（`error.network`）。**不降级**：401/403（密钥/权限）、404（模型名/路径）、400/422（参数）、`AbortError`（用户中断）与配置指纹变化。判据优先用结构化字段（`api.js` 在失败构造点挂 `httpStatus`/`timeout`/`network`），文案匹配只作兜底。
- **「已产出」是硬条件**：包装调用方传入的 `onChunk`/`onReasoning` 打标，一旦回调过就禁止降级（流式已吐出半句话再换模型 = 用户看到两段拼接的回复）。
- **按模型重算的三项**：每次尝试都重算该模型的能力（`capabilitiesForModel`）、输出预算（`max_tokens`）与上下文裁剪（`contextWindow`），避免降级后仍用主模型的窗口/预算。
- **如实告知**：换模型前调用 `options.onModelFallback({ from, to, attempt, reason })`（回调抛错不影响重试）。聊天页经 `runAgentTurn` 的 `onModelFallback` 透传，在输入栏上方显示「已切换到 X」提示条（`useChatSend.modelFallbackNotice` → `ChatScreen`），随本次发送结束消失。
- **未做**：降级后的用量/费用归属仍记在主模型名下（与 P2-10 一起定）。

### 错误处理

- 未配置密钥时抛出提示，不发起请求
- 空闲超时（30 秒无增量）转换为固定中文文案
- 非 2xx 响应优先取后端 `error.message`，HTML 响应退化为 `请求失败（HTTP <status>）`
- SSE 流中出现 `error` 负载时立即抛错并中断
- 服务端忽略 `stream` 而返回整包 JSON 时回退解析 `choices[0].message.content`
- 2xx 但响应既非 SSE 也非可解析 JSON 时抛出无法解析错误
- SSE 流内所有 `data:` 行都无法解析为 JSON 时同样抛出无法解析错误，避免显示空回复掩盖问题
- 收到 `data: [DONE]` 时立即结算并中断，避免服务端保持连接导致空闲超时
- 传入 `signal` 且被取消时，以 `AbortError` 拒绝并移除监听；未取消的异常中断为 `请求已中断。`
- 空响应统一返回 `'没有收到回复。'`

## 调整请求行为

1. 修改空闲超时时长：调整 `sendChatMessage` 中的 `IDLE_TIMEOUT_MS`
2. 支持额外请求头或参数：在 `xhr.setRequestHeader` 与 `xhr.send` 的 body 中扩展
3. 解析更多流式字段：扩展 `extractDeltaContent`
4. 若未来 RN 版本支持 `response.body`，可改回 `fetch` 流式读取，但需同步更新本文档
