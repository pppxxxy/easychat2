# 界面层

界面层负责应用外壳、导航与三个功能页面，是用户可感知的全部交互入口。

## 结构

```
App.js                    # 应用外壳、导航容器与底部标签
src/
├── ChatScreen.js         # 聊天页：消息列表、发送、错误气泡、持久化
├── CharacterScreen.js    # 角色页：编辑角色、导入角色卡、展示扩展数据
└── SettingsScreen.js     # 设置页：API 地址、模型与密钥
```

## 关键文件

| 文件 | 目的 |
|------|------|
| `App.js` | 启动垫片、`AppProvider`、`NavigationContainer`、三个 `Tab.Screen`，并渲染全局 `Header` |
| `src/ChatScreen.js` | 聊天主流程；包含 `MessageBubble`/`ErrorBubble` 两个内部组件与 `markdownStyles`；发送前经 `chatPipeline` 组装消息，展示前经 `regexEngine` 应用正则；会话为空且角色有 `firstMes` 时注入开场消息 |
| `src/CharacterScreen.js` | 角色 6 个核心字段可编辑保存，保存时用 `buildSystemPrompt` 合成 `systemPromptComposed`；PNG/JSON 角色卡导入；世界书与正则以可折叠区块逐条编辑与增删；多行输入限制最大高度避免撑爆页面滚动 |
| `src/SettingsScreen.js` | API 配置读写与 HTTP 明文确认 |

## 依赖

**本模块依赖**:
- `../src/context/AppContext` - 读取当前角色与更新方法
- `../src/storage` - 消息与配置持久化
- `../src/api` - 发送聊天请求
- `../src/chatPipeline` - 组装含世界书与正则的请求消息
- `../src/regexEngine` - 展示时应用 AI 输出正则
- `../src/cardParser` - 解析 PNG/JSON 角色卡
- `../src/secrets` - 报错脱敏
- `react-native-markdown-display` - 渲染助手 Markdown
- `expo-document-picker`、`expo-file-system`、`parsecard` - 角色卡导入

**依赖本模块的**:
- 无（位于依赖树顶层）

## 规范

### 文件命名
- 页面组件：`<Name>Screen.js`，默认导出同名组件
- 页面内私有组件：同文件内以 PascalCase 函数定义

### 代码模式

**页面组件结构**:
```javascript
export default function XxxScreen() {
  const { character, loaded, updateCharacter } = useApp();
  const [state, setState] = useState(initial);
  // 副作用与处理函数
  return (
    <KeyboardAvoidingView ...>
      <ScrollView ...>{/* 内容 */}</ScrollView>
    </KeyboardAvoidingView>
  );
}
```

**异步提交与提示**:
```javascript
try {
  await updateCharacter(next);
  Alert.alert('已保存', '...');
} catch (error) {
  Alert.alert('保存失败', '请检查存储空间或权限。');
}
```

### 样式

- 每个文件底部用 `StyleSheet.create` 定义样式
- 统一暗色板：背景 `#1a1a2e`、输入/卡片 `#2d2d44`、主色 `#6c63ff`、次要文字 `#aaa`
- 禁用态 `opacity: 0.45`

### 错误处理

- 所有展示给用户的错误都通过 `Alert`，写入类异常在界面层捕获
- 聊天报错与角色卡解析报错都必须经 `src/secrets.js` 的 `maskSecrets` 脱敏后才可展示或落盘
- 流式失败且已收到部分文本时，保留该部分回复（标记为完成），并在其后追加系统报错消息
- 主动取消不产生系统报错：`isCanceledError` 为真时保留已收到的部分回复，无文本则移除占位
- 角色卡 PNG 无数据与解析失败给出不同提示，解析失败附带脱敏详情

### 生成控制

- 生成中发送按钮切换为「停止」，点击调用当前请求的 `AbortController.abort()`
- 切换角色与组件卸载时中断进行中的请求，避免后台空耗流量与电量
- 每个请求持有独立的 `AbortController`，`finally` 中清空 `abortRef` 防止误用

### 聊天滚动

- 消息列表在内容增长时（`onContentSizeChange`）自动滚到底部
- 仅当用户处于底部附近（阈值 80px）才执行，用户上滚查看历史时不被流式增量打断
- 发送新消息时强制重置到底部状态并滚动，确保新消息可见

### 测试

项目当前无自动化测试，界面改动通过 `npm run start` 在真机/模拟器手动验证。

## 添加新页面

1. 在 `src/` 新建 `<Name>Screen.js`，默认导出组件
2. 复用暗色样式常量
3. 在 `App.js` 导入并新增 `<Tab.Screen name="..." component={...} />`
4. 如需全局状态，通过 `useApp()` 获取
5. 用 `npm run start` 验证导航与交互

**检查清单**:
- [ ] 组件默认导出
- [ ] 样式与现有页面一致
- [ ] 已注册到 Tab 导航
- [ ] 存储调用有异常处理
