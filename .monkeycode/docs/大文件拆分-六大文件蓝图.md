# 大文件拆分：六个大文件蓝图（2026-10-12，m1012m30）

> 承接 `.monkeycode/docs/审查待办.md` 的「第 3 项大文件拆分」。第 15–20 刀已把 15 个超 800 行
> 文件降到 9 个；其中 3 个（`chatStyles.js` / `CardForgeEditor.js` / `FilesPanel.js`）仍可按小文件节奏拆，
> **本文件专门规划剩下的六个「大头」**。这六个互相耦合深、被大量源码断言锚定，必须按「单元清单 +
> 依赖图 + 断言影响面」逐刀推进，不能照小文件节奏盲切。

## 目标与口径

- 目标：把六个文件各自拆到 ≤ 800 行（`architecture-baseline.json` 行数棘轮，阈值 = 实际值、不留余量）。
- 硬约束：行为逐字不变；不改公开导出面（除非同步改调用点）；不引入循环依赖（`guard:structure` 拦）。
- 每刀完成后：`npm run lint` 零输出、`npm run guard:structure`、`npm test`、`npm run test:coverage`、
  `npx expo export --platform android` 全绿；基线同步下调，≤800 即从基线移除并记 `_baselineChangeLog`。

## 通用协议（每刀照做）

1. **选内聚单元**（一个 hook / 一个展示组件 / 一组同域状态与编排），不按行数硬切。
2. **外提为同目录模块**：展示组件传 `styles/theme/t` + 既有 state/handler；状态编排抽 hook，依赖经参数注入。
3. **先查断言**：`rg '<该单元里的字符串>' tests/*.mjs`；被钉住就把对应测试改成读新文件
   （**不删断言、不弱化判据**）。这些文件普遍是「源码字符串断言」，这是本项最大的摩擦来源。
4. **登记排除**：新 UI/hook 文件写进 `.c8rc.json` 的显式 `exclude` 清单（不用后缀通配）。
5. **行号会漂移**：本文件的行号是 2026-10-12 快照，动刀前用函数名重新定位，不要按行号机械替换。

## 建议总顺序（低风险 → 高风险）

`GithubPanel` → `CharacterDetailScreen` → `ChatPanel` → `useChatSend` → `SettingsScreen` → `ChatScreen`。
前两个域边界较清；`useChatSend`/`ChatScreen` 是聊天主链路，断言最密（各 20+ 个测试文件），放最后。
