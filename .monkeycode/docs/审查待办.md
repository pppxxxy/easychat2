## ⏸ 主动消息功能缺口：消息从不落库（已立项为独立 spec）

> 用户反馈：定时主动消息**到点后聊天里完全没有消息**，点开角色卡也没有任何消息。经核对代码，根因不是「通知没送达」，而是**主动消息从来没有被写入会话**：
> - `ProactiveMessageSender.send` 生成文本后**只发通知**，不写任何消息存储；
> - 通知的 PendingIntent **只带 `roleId`，不带文本**；
> - 因此「点开角色卡没有消息」是必然结果。
>
> 已立项独立 spec：`.monkeycode/specs/2026-09-29-proactive-message-persistence/`（需求/设计/任务）。方案：原生把生成的消息写入待写队列（SharedPreferences），JS 在启动与 `onOpenRole` 时消费并写入目标角色单聊会话；通知降级为提醒。
>
> 事件送达（点通知能否跳转）作为**次生问题**：本 spec 落地后若仍跳不过去，再作为独立 bug 用真机 logcat 排查（`onHostResume` 读 `currentActivity?.intent` 时序、`consumeInitialRole` 与 `onHostResume` 争抢 pendingRoleId、热启动是否进 `onNewIntent`）。

## 角色页「未保存」误报（用户报告，本轮已修复）

> 用户报告：角色页什么都没改，切换角色也一定弹「有未保存的编辑」；要求只在真正改了未保存时才询问。核验：静态签名稳定（用真实 `ensureUniqueIds` 模拟 13 类角色——空卡/世界书无 id/正则/预设缺字段/avatar 空/alternateGreetings/AI 卡带 aigcMeta——`currentFormState` 与 `characterFormSignature(character)` 全部逐字相等），排除键名与序列化问题；集合 state 也没有 seed 后的自动改写路径。根因在脏判定的**参照物**。

- [x] **根因**：`formDirty = currentFormSignature !== savedFormSignature`，后者取「角色**当前内容**」。角色内容会被后台更新（记忆摘要写入世界书、其他页面保存、AppContext 重建），一更新就让未动过表单的用户被判「有未保存修改」——切换角色（onSwitch 与 seed effect 的外部切换拦截）与切 Tab（上轮 guard）全部误弹。
- [x] **修复**：改为「表单 vs 本角色 seed 时的表单快照」并加 formReady 闸门——`formDirty = formReady && currentFormSignature !== seededFormSignatureRef.current`。外部更新仍由 seed effect 的 `externalChanged`（生成本落库后自动同步表单）与 `externalConflict`（用户改了且外部也改时保留编辑、保存时提示覆盖）两条既有机制处理，语义自洽：用户改表单 → 脏；后台更新角色 → 不脏且表单自动同步；保存后基准推进。
- [x] **回归**：源码断言（必须用 seeded 基准 + formReady 闸门，旧口径不得回潮）。`npm test` 324/324，`npm run lint` 无输出。真机待验：进入角色页不做任何编辑，点其他角色卡与切 Tab 均不再弹窗；真正编辑后未保存时仍正确询问。
