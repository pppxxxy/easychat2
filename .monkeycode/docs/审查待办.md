## ✅ 已修复：主动消息点通知不跳转（原「未解历史 bug」）

> 用户反馈：定时主动消息**模块能加载**（`isProactiveMessageAvailable()` 为真），但**点通知不跳转到对应角色**。旧版（SDK 50）即存在，与 SDK 54 无因果。

**根因（确定性，非玄学时序）**：`ProactiveMessageBridge` 的监听 effect 不受 `loaded` 门控，挂载即注册。冷启动链路：

1. 原生 `onHostResume` 抓到启动 intent → `queueRoleOpen` → `drain()`（listener 已注册）→ **清空原生 `pendingRoleId`** 并 emit 事件；
2. JS `openRole` 收到后若 `navigationReady` 已 true，直接走 `switchCharacter(roleId)`（`App.js`）；
3. 此时 `loadedRef.current` 仍为 false → `switchCharacter` 抛「角色尚未加载完成」（`src/context/AppContext.js`）；
4. `openRole` 的 catch 只弹「打开失败」，**roleId 未入队**；原生侧也已在 drain 时清空 → `consumeInitialRole()` 再取为 `null`。

即 **roleId 被消费一次后永久丢失**，冷启动必现；「导航就绪后消费」effect 依赖不含 `loaded` 时同样会抛后丢。

**修复**：
- JS：`openRole` 与消费 effect 都同时门控 `loaded`，未就绪一律入队，绝不调用会抛错的 `switchCharacter`；`openRole` 依赖数组补 `loaded`。
- 原生（`ProactiveMessageModule.kt`）：`pendingRoleId`/`listenerCount` 跨线程（UI 线程 vs NativeModules 队列线程）加 `lock` 同步；新增 `captureLaunchIntent()`，在 `init`/`onHostResume`/`addListener` 三处兜底抓启动 intent，覆盖 `currentActivity` 晚于 `onHostResume` 就绪的冷启动。
- 回归：`tests/proactiveMessageBridge.test.mjs` 断言两处 `loaded` 门控；`tests/proactiveMessagePlugin.test.mjs` 断言同步锁与 `captureLaunchIntent`。`npm test` 479/479，`npm run lint` 无输出。**真机待验**：冷启动/热启动各点一次通知能否跳转。

## ✅ 已修复：主动消息消息从不落库（原功能缺口）

> 用户反馈：定时主动消息**到点后聊天里完全没有消息**，点开角色卡也没有任何消息；点通知跳转后是**白屏**。经核对代码，根因不是「通知没送达」，而是**主动消息从来没有被写入会话**：
> - `ProactiveMessageSender.send` 生成文本后**只发通知**，不写任何消息存储；
> - 通知的 PendingIntent **只带 `roleId`，不带文本**；
> - 因此「点开角色卡没有消息 / 点通知后空白会话」是必然结果。

> **修复**（spec：`.monkeycode/specs/2026-09-29-proactive-message-persistence/`，已按任务清单落地）：
> - 原生：`ProactiveMessageSender.send` 发通知前先 `appendPendingMessage` 入待写队列（SharedPreferences，上限 100 条 / 超 7 天淘汰）；新增 `consumePendingMessages`（**不清空**）+ `ackPendingMessages(ids)`。

> - **附加需求（用户追加）**：每个时间槽可选消息类型 `DEFAULT`/`CARE`（关心心情）/`GREETING`（问好，按时段自动选早/中/晚）/`CUSTOM`（自定义提示词）；面板提供类型 chips 与自定义输入框，原生 `buildSystemPrompt` 按类型组装提示词，`FallbackMessages` 的 `CARE` 用独立文案。

### 关键约束（必须遵守，否则会踩既有坑）

- **密钥**：`@easychat2_api_configs` 里密钥被 `secretStore` 抽到 `expo-secure-store`，AsyncStorage 只剩 `secure:v1:<id>` 引用（`src/secretStore.js`）。导出**不能**把这些引用当明文导出（换机后无法解析）。二选一并在 UI 明示：默认**不含密钥**（导入后用户重填）；或提供「含密钥导出」二次确认，导入时经 `protectSecrets` 重新落安全存储。
- **大值**：消息/角色卡可能超过 AsyncStorage 单值 2MB 读取上限（走 SQLite fallback，见 `src/storage/io.js` `readLargeAsyncStorageValue`）。导出读取必须复用该 fallback，不能只 `getItem`。同理导入写大值要分键。
- **绝不整表单键**：角色/表情包/日记已是「索引 + 单条分键」。导出格式可扁平化，但导入必须按既有分键写回，禁止把整个集合塞进一个键。
- **pending 占位不落盘**：`pending: true` 的助手占位消息永不持久化（`storage.js`/`ChatScreen` 都过滤）。导出前也要过滤，导入后不得复活。
- **导入是覆盖还是合并**：需产品确认。建议默认「合并（按 id 去重，冲突以导入方为准）」并支持「清空后恢复」；覆盖式导入要做原子性（先写临时索引后切换，参照角色库「index 最后写」的提交点约定）。
- **格式与版本**：导出文件带 `schemaVersion` 与 `appVersion`；导入时按版本做迁移或拒绝，避免旧结构直接覆盖新结构。
- **体积与上限**：含媒体时文件可能很大。参照 `cardExporter.MAX_CARD_FILE_BYTES`（32MB）设定上限与超限提示；建议提供「仅数据（不含媒体）」「含媒体」两档。
- **权限与路径**：用既有 `expo-document-picker`（选文件）+ `expo-sharing`（分享导出，见 `ImageGenScreen`/`CharacterScreen` 先例），不新增依赖。
- **导入校验**：导入前校验 JSON 结构与 `schemaVersion`，损坏文件不得写入；解析失败保留现场不破坏现有数据。

## 角色页切 Tab 一定弹窗且「保存并离开」离不开（用户报告，本轮已修复）
