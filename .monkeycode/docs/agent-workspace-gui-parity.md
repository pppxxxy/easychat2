## 0. 比较前提（先说清，否则结论会跑偏）

| | EasyChat2 工作区 | DSH 桌面端 |
|---|---|---|
| 形态 | **移动端**（Expo/RN）全屏 Modal | **桌面**（Electron 壳 + 同一套 SPA；浏览器走 HTTP，Electron 走 `file://` + IPC 桥接 fetch） |
| 交互前提 | 手指、窄屏、无常驻键盘 | 鼠标、宽屏、键盘为主 |
| UI 规模 | `src/workspace/screen/` 9 个文件 ≈ 6200 行（面板是**整体**） | **62 个 client 包 / 其中 53 个 `client-ui-*`**，中文 README 合计 4495 行 |
| 扩展模型 | 文件即配置（SKILL.md / commands / agents / hooks.json） | **cordis 插件**：UI 包按需加载成浏览器 bundle，往类型化 slot 注册 |
| 布局 | 无 resize、无拖拽（全 `src/workspace/**` 无 `PanResponder`/`Animated`） | 三栏几何由 `computeColumns()` **解算**（不是 CSS），可拖动、可全屏接管 |

**所以「DSH 有的我们都该有」是错的判断。** 下面按「移动端是否成立 + 与既有裁决是否冲突」筛过。

## 1. 骨架对照

| 维度 | 我方 | DSH |
|---|---|---|
| 根结构 | 唯一全屏 Modal（`WorkspaceScreen.js:98`）+ 左栏 76px 图标轨五领域（`:31-37,195-202`） | 唯一一次 `renderSlot('root')`，root 只有 **5 个子槽**：`sidebar`/`main`/`rightbar`/`shell.overlay`/`shell.leading`（`ui-layout/lib/client.js:605-621`） |
| 同时可见 | **只有一个面板**——内容区条件渲染（`:139-165`），「面板单开」是刻意设计 | 三栏并存；左栏 264–420px（默认 280，收起留 56px 轨，`<1024px` 自动收起）、中栏保底 400px、右栏 300px–70%（首开 45%） |
| 让步顺序 | 不适用 | 先缩右栏到 300px → 报告空间不足让占用方自己关 → 最后才压中栏 |
| 右栏 | 无 | **可停靠面板轨道**：最多**两格**（分隔条 20%–80%）、`push`/`fullscreen` 两种呈现、`<768px` 自动全屏、**没有标题行**、布局按会话持久化到 `localStorage` |
| 二级层 | 压到面板内层或底部 sheet（`FileHistorySheet.js:186`），层深 ≤2 | 右栏 **tab 类型注册表**：7 种 tab（文件树/文档预览/终端/浏览器/计划/子代理对话/引导页），两阶段注册，档位 `extension > builtin > fallback` |
| 中栏 | 单一 ChatPanel | `main` 的 keyed 槽 `conversation`：内含 **View 环**（Chat / Trajectory 等注册于此）、composer chain（临时接管）、**9 个 input 座位** |

**结论**：骨架差异是**根本性**的，不是「少几个功能」。DSH 的信息架构建立在「多栏并存 + 面板可停靠」上；我们是「单面板切换」。手机屏幕确实放不下三栏——但这条决定了下文 P1。

## 2. 功能面差距（按我方是否成立筛选）

### 2.1 真差距，且移动端成立

| DSH 的界面能力（包） | 它给用户什么 | 我方现状 |
|---|---|---|
| `client-ui-tool` | **按工具名键控的视图 slot** + 完整调用树 + 原子工具卡片 | ⚠️ **工作区只有一行会闪过的 `toolStatus`**（`ChatPanel.js:1188,1486-1491`）；`ToolBubble` 只在聊天页用（`MessageList.js:193`）；轨迹已落盘却不展示（`ChatPanel.js:1281-1282`） |

| `client-ui-shortcuts` | **18 条可编辑快捷键** + 固定输入操作 + 录制/冲突检测/按设备默认/持久化 | ❌ **全仓无任何快捷键**（无 `onKeyPress`/`KeyCommand`） |

### 2.3 DSH 有、但我们**不该照搬**（已裁决或物理不可行）

- **LSP / 语言服务器**：Android 沙盒无 node 运行时，`2026-10-10-agent-d` 已列「物理不可行」。
- **53 包插件化 UI**：我们单文件已撞架构棘轮（`ChatPanel.js` 1853 行卡基线），先解决「面板怎么拆」。
- **完整键位录制系统**：桌面形态的产物（6 种设备×平台、双键组合、冲突校验）。移动端价值低——**但平板 + 外接键盘值得一个极小子集**（见 P5）。
- **Electron 内嵌浏览器**：场景不同（DSH 是「让 agent 起服务、我顺手看一眼」）。
- **Plan DAG / 工具结果向量检索 / 上下文老化淘汰**：`2026-10-09-agent-capability` 已明确不做。

### 2.4 DSH 自己的短板（**别照抄**，如实记录）

- **几乎无右键菜单**：全仓 `onContextMenu` 仅 1 处且是 `preventDefault()`；靠「…」菜单 + 悬停按钮拼装。
- **文件树明确没有搜索/拖拽/重命名/右键**；目录选择对话框也**无搜索、无多选、无重命名/删除**。
- **面板几何是瞬时状态**：刷新即恢复默认并隐藏右栏；拖动宽度是**全框架共用一份**偏好，不是每会话属性；挤压重排期间**无滚动锚定**。
- **没有面向用户的撤销/重做**（右栏布局历史只由 `@internal` 驱动）；**没有 History API 路由**。
- 声称拥有分裂树/浮窗的 `client-ui-dockkit` **不在 62 包名单里**，实现未随包提供——这条能力**未能确认**。

### 2.5 我方反超、DSH 界面里没有对位的

- **诚实优先的界面**：能力矩阵卡如实列边界与当前生效工具（`WorkspaceCapabilitiesCard.js:24-56`）、终端把「无流式 / 跑不了 vim / 环境变量不跨命令」写进常驻文案（`TerminalPanel.js:301`）、审批显示命令**原文不截断**并说明「为什么这里没有永远允许」（`toolApproval.js:74-75`）。
- **主动性**：主动消息 + 定时 Agent 任务（DSH 有 `client-ui-schedule`，但语义是桌面定时任务，不是「角色主动找人」）。
- **看屏悬浮窗**（跨应用截屏/观屏）、**本地模型 + 本地 OpenAI 兼容 server**、**模型无关**。
- **单屏单面板是结构性保证**：让「Modal 叠 Modal」在结构上不可能出现（`WorkspaceScreen.js:1-13,139-165`）——这是 DSH 没做的取舍。

## 4. 结构差距（一句话）

- **我方**：`screen/**`（RN UI）↔ `workspace/*.js`（纯逻辑，可 Node 直测）↔ `agent/**`（内核）。**分层干净**，但 UI 层是**整体式面板**——加功能只能往大文件里塞（已撞棘轮）。
- **DSH**：宿主（`host-webserver` 纯路由表 + 唯一回退席位 / `host-frontend-static` 发 SPA dist）+ **客户端模块加载器**（`client-modules` 把插件 `dsh.client` 声明变成按需加载的浏览器 bundle）+ **类型化 slot**（`client-ui-slots`：四种 kind、「声明即认领」、加载期报冲突）+ 视图注册表。UI 能力是**被注册进来的**，不是被写进去的。
- **可借鉴的最小内核**：不是 53 个包，而是「**一个 slot 注册表 + 面板自注册**」这个形状——它能让 `FilesPanel`/`GithubPanel` 各自把「右栏 tab / 会话头部卡片 / 轮末卡片」注册进来，而不是全部塞进 `ChatPanel`。

## 5. 规划（按「价值 ÷ 成本 × 与既有裁决兼容」排序）

> 纪律：每项独立交付、门禁全绿、行为测试；碰 UI 的按 `SMOKE_TEST.md` 走查。
> 与 `agent-harness-parity.md` 的补齐顺序（真实执行环境 → 多智能体编排 → SDK…）不冲突，这是**界面线**。

### P0 工具过程可见（最大体验缺口，成本最低）
工作区现在**看不到 agent 干了什么**——这是用户最能直接感知的差距，而且**材料已经现成**：
- `src/chat/toolBubbleView.js` 已是**纯函数**（把 `onToolEvent` 映射成气泡视图），`src/chat/ToolBubble.js` 是现成组件，只是没被工作区引用（`MessageList.js:193`）。
- 做法：把 `toolStatus` 一行（`ChatPanel.js:1486-1491`）升级为**逐工具卡片列表**：工具名 / 参数摘要 / 成功失败 / 耗时 / 落盘指针（O1 已有 `.task_outputs/` 路径）。
- 顺带把已落盘但未展示的 `toolTrace`（`ChatPanel.js:1281-1282`）接上，让「上一轮读了什么」也能回看。

### P1 宽屏第二栏（结构缺口，**需裁决**）
- 现状「面板单开」是**刻意设计**（`WorkspaceScreen.js:1-13`，为根除 Modal 嵌套）。**不建议推翻**，建议**按宽度分流**：
  - 窄屏（手机竖屏）：保持单开，一行不动。
  - 宽屏（平板/横屏/折叠屏展开）：对话常驻 + 右侧**一个**可停靠面板（文件 / 终端 / GitHub 三选一），可拖动调整宽度（对标 DSH 的两格 + 20%–80% 分隔条）。
- 代价：引入 `PanResponder` + 宽度持久化（现在全仓没有），且要重述「单开」原则。
- **这是本规划唯一需要你先拍板的**：接受「宽屏允许两栏」，还是维持「永远单面板」？

### P2 检索与导航（成本中，收益直接）
- 聊天消息搜索、会话历史搜索、本地文件搜索——**照抄 `GithubPanel.js:1262-1281` 已有的搜索形状**，不发明新的。
  （注意：**这不是「抄 DSH」**——DSH 的文件树同样没有搜索。这是独立改进。）
- 会话历史加排序（现在只有「全部 / 已归档」两个过滤，`WorkspaceHistorySheet.js:44-47`）。

### P3 扩展点 GUI 补齐（成本低，消除「文件即配置但看不见」）
- **子代理档案**：与技能行对齐（至少计数 + 列表）——**已完成（P3-1）**。此前零入口：`ChatPanel`
  每轮都 `readWorkspaceAgents` 读进系统提示词，但界面一个字都不显示。
- ~~**技能**：从「只有数量 + 装示例」升级为逐条列表~~ —— **本条是错的，已作废**：技能行
  **本来就有逐条列表**（`WorkspaceSettingsSheet.js:404-416` 的 `skills.map` 输出「名字：描述」）。
  初版文档照抄了子代理报告里的一处失准描述，核对代码时发现，特此更正。
- **MCP 入口**：入口只在主设置页（`SettingsScreen.js:1785-1796`），工作区里没有指过去的路。
- **会话事件流**：已落盘（`sessionEvents.js`）却**没有界面**——现有的是「导出」动作行，
  不是「看这一轮发生了什么」的只读视图。
- **MCP**：入口现在只在主设置页（`SettingsScreen.js:1785-1796`），工作区里给一条链过去的路。
- **会话事件流**：已落盘（`sessionEvents.js`）却无界面——做一个只读的「本轮发生了什么」列表（DSH `trajectory` 的轻量对位，不是事件溯源级日志）。

### P4 收尾与一致性（成本极低，先做）
- `WorkspaceScreen.js:163` 给 `WorkspaceSettingsPanel` 传了 `onClose`，但组件签名不接收（`WorkspaceSettingsPanel.js:22`）——面板化改造的尾巴。
- 上下文占用两处重复 → 收敛为单一来源。
- `.monkeycode/docs/专有概念/工作区.md:20-22` 描述的左栏（新建对话/新建项目/查找历史/综合设置）**已过时**，代码是五领域图标轨（`WorkspaceScreen.js:31-37`）——文档滞后于代码。
- 90 处 `Alert.alert` 里，**确认类**（删除/覆盖/推送）值得逐步换成面板内确认条，把系统弹框留给「必须打断」的场景。

### P5 移动端手势与极简键盘（低优先，量力）
- 移动端**不要照抄键位系统**；对应物是手势：面板间横滑切换、列表滑动操作、长按菜单。
- 平板 + 外接键盘可给**极小子集**（发送 / 停止 / 切换面板），排在 P0–P3 之后。

### 明确不做（沿用既有裁决，防被外部分析带偏）
LSP 集成（物理不可行）｜ 53 包插件化 UI ｜ 完整键位录制系统 ｜ Electron 内嵌浏览器 ｜ Plan DAG ｜ 工具结果向量检索 ｜ 上下文老化淘汰 ｜ 重做 MCP 泛化 / `run_subagent` / SKILL.md 基础格式。

## 6. 一句话

DSH 桌面端的界面优势**不在「功能多」**，而在两件事：① **多栏并存 + 面板可停靠**（把 agent 的工作过程摊开在同一屏）；② **一切都可被插件注册进来**（所以它能长出 53 个 UI 包，而我们只能往大文件里塞）。
我们**立刻能吃到的是 P0（工具过程可见）+ P4（收尾）**——材料现成、不动架构；真正要动结构的是 **P1（宽屏第二栏）**，而它需要先回答一个问题：**「面板单开」这条原则，在宽屏上要不要破例。**
