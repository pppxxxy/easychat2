## 〇、0b 真机验证结果与修复（最新，先看这一段）

0b（`chore/sdk54-newarch-probe`）真机实测：

- **跳转通过**：冷启动、热启动点通知**都能切到配置角色的聊天页** → 说明 Interop 的模块注册、`@ReactMethod`（`consumeInitialRole`/`schedule` 返回 String/Map）、`RCTDeviceEventEmitter.emit` 事件链**全部可用**。
- **落库失败**：A/B/C 三种路径聊天与记忆里都没有那条主动消息。
- **判定**：Interop「半通」——`consumePendingMessages` 是唯一返回 `WritableArray<WritableMap>` 的方法，新架构下数组跨桥编组不可靠，JS 侧 `Array.isArray` 不成立 → `consumePendingMessages` 静默返回 `[]` → 不落库、不 ack。**不必开 0c**。
- **修复（本次）**：
  1. 原生 `consumePendingMessages` 改返回 **JSON 字符串**（不再 `Arguments.createArray`）；`ackPendingMessages` 入参改 **JSON 字符串**（不再 `ReadableArray`）。字符串契约与 `schedule`/`consumeInitialRole` 一致、已验证可用。两处加 release 可见 `Log.i(TAG, "consume pending n=…")`。
  2. JS `src/proactiveInbox.js` 新增纯函数 `normalizePendingMessages`，兼容「普通数组 / JSON 字符串 / 类数组 HostObject / 单条对象」，`consumePendingMessages` 统一归一；`ackPendingMessages` 传 `JSON.stringify`。
  3. `App.js`：启动消费结果直接传给 `openRole`（不再重复消费）；新增 **AppState 回前台消费一次**（修掉「到点后自己切回 App」无消费入口的架构无关缺口）。
  4. 诊断：每轮消费写一条 `recordDiagnostic`（release 可见，免 adb），在「设置 → 关于 → 诊断日志」可看 `主动消息消费：取N 写N 删N 缓N`。
- **重打 0b 后复验**：设 1~2 分钟精确槽 → 等通知 → 点通知/切回 App，聊天与记忆应出现消息；若仍无，看诊断里的「取N」：`取0` = 队列没读到，`取1 写0` = 角色不在库/写入失败。

## 一、当前分支结构（关键）

同名提交在三处各有一份（cherry-pick），功能代码一致，**不要直接 merge**，沿用 cherry-pick 同步。

| 分支 | 用途 | 关键差异 |
| --- | --- | --- |
| `main` | 主线，功能开发都在这里 | 基线 |
| `chore/sdk54-upgrade`（简称 **0a**） | SDK 54 保底基线 | `app.json` 的 `newArchEnabled:false` |
| `chore/sdk54-newarch-probe`（简称 **0b**） | 新架构验证 | `newArchEnabled:true` + `App.js` 里的 `[INTEROP_PROBE]` 探针 |

- 0a/0b 相对 main 的差异**仅限 SDK 54 必需项**：`package.json`/lockfile 版本、`expo-file-system` 全量切 `/legacy`、`withProactiveMessage.js` 的 SDK54 `apply{}` 模板补丁、`ProactiveMessageModule.kt` 的 RN0.81 非空签名、上面两处 app.json/App.js。
- 每次在 main 完成一批改动后，用 `git cherry-pick <sha>` 同步到 0a 与 0b（0b 的 App.js 常与探针行冲突，手动合并即可），跑 `npm run lint` + `npm test` 后各自 push。
- **不要手改 `android/`、`ios/`**：gitignored，`expo prebuild --clean` 会重建。

## 二、升级路线与版本链（已确认，勿再调研）

升级是「依赖绑定整体升级」，不是可选项：

- Expo SDK **50 → 54**、React Native **0.73 → 0.81**、React **18 → 19**、`newArchEnabled` 关→开。
- 版本依赖链：**先升 SDK 54（0a/0b）→ 若新架构 Interop 不行再迁原生（0c）→ 再迁 `expo-av`→`expo-audio`（0d）→ 才好干净地做语音消息**。
- 阶段划分（来自 spec，无独立路线图文件）：**阶段 1 = 纯 JS 陪伴**（不依赖原生工程/本地模型）；端侧转写（`expo-speech-recognition`）属后续阶段。

## 七、易踩的坑（详见 AGENTS.md，这里只列最容易忘的）

- `src/package.json` 的 `{"type":"module"}` 不可删；`src/**` 相对导入一律带 `.js`。
- 存储键有单值 2MB 读取上限：大集合必须「索引 + 单条分键」；导出/备份勿整表存一键。
- 测试加载 `src/storage/*` 子模块时**必须写回 `Module._cache`**，否则模块级共享状态被复制。
- Kotlin 源码无编译器可验，`tests/proactiveMessagePlugin.test.mjs` 用「大括号平衡 + 顶层声明不重复」兜底。
- 提交前跑门禁；一个主题一个提交；未经用户明确要求不要 commit/push。
