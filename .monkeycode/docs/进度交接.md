## 〇、0b 真机验证结果与修复（✅ 已通过，先看这一段）

**结论：新架构 Interop 对旧式原生模块可用，零改造，不需要迁 TurboModule（不开 0c）。** 0b 真机最终复验全过：

- 冷启动、热启动点通知**都能跳转**到配置角色聊天页，且落在**含新消息的那段会话**；
- 主动消息**落库成功**（聊天 + 记忆都出现该条消息）；
- 槽的**「衔接对话」**也更新为本次会话（`bindProactiveSlotSession` 生效）。

排查过程（两个 bug 都在 JS/契约层，与 TurboModule 无关）：

1. **数组跨 Interop 编组不可靠**（第一轮）：`consumePendingMessages` 是唯一返回 `WritableArray<WritableMap>` 的方法，新架构下 JS 侧 `Array.isArray` 不成立 → 静默返回 `[]` → 主动消息永不落库。**修复**：原生改返回 **JSON 字符串**、`ackPendingMessages` 改收 **JSON 字符串**；JS `src/proactiveInbox.js` 新增 `normalizePendingMessages` 兼容数组/字符串/类数组。两处加 release 可见 `Log.i(TAG, "consume/ack pending n=…")`。
2. **并发消费丢 `targetSessions`**（第二轮）：冷启动时启动 effect 与 `onOpenRole` 事件并发消费同一队列，先完成方 ack 清空、另一方取空 → `openRole` 拿不到「消息落在哪段会话」→ 停在默认会话看不到消息。**修复**：`ingestPending` 用 **in-flight Promise 合并并发消费**、把 `roleId → sessionId` 缓存进 `targetSessionRef`，`openRole` 拿不到本轮映射时回退缓存；新增 `主动消息跳转：角色X 目标会话Y` 诊断。
3. 顺带修：`App.js` 补 **AppState 回前台消费一次**（「到点后自己切回 App」原本无消费入口）。

诊断（release 可见，免 adb）：「设置 → 关于 → 诊断日志」可看 `主动消息消费：取N 写N 删N 缓N` 与 `主动消息跳转：角色X 目标会话Y`。

回归：`tests/proactiveInbox.test.mjs`、`tests/proactiveMessagePlugin.test.mjs`、`tests/proactiveSettings.test.mjs`。当时 `npm test` 545/545（0b 上 547/547）、`npm run lint` 无输出、覆盖率 84.65%；**当前基线以第六节为准**。

## 七、易踩的坑（详见 AGENTS.md，这里只列最容易忘的）

- `src/package.json` 的 `{"type":"module"}` 不可删；`src/**` 相对导入一律带 `.js`。
- 存储键有单值 2MB 读取上限：大集合必须「索引 + 单条分键」；导出/备份勿整表存一键。
- 测试加载 `src/storage/*` 子模块时**必须写回 `Module._cache`**，否则模块级共享状态被复制。
- Kotlin 源码无编译器可验，`tests/proactiveMessagePlugin.test.mjs` 用「大括号平衡 + 顶层声明不重复」兜底。
- `src/chat/` 下可测模块**不得触碰 expo/RN 依赖**，否则 Node 测试直接加载失败；需要外部能力时以参数注入。
- hook 拆分后有两道永久守卫：`chatScreenSplit.test.mjs` 的声明顺序测试（防 TDZ）与双向参数匹配测试（防签名/调用点不一致）——新增 hook 参数必须同步改调用点，否则测试直接红。
- 提交前跑门禁；一个主题一个提交；未经用户明确要求不要 commit/push。
