# 需求文档：流式输出开关

## 简介

新增「流式输出」开关，控制助手回复是否以逐字增量方式呈现。开关关闭时，系统改用整包响应，收到完整回复后一次性展示。开关状态持久化，默认开启以保持现状。

## 术语表

- **流式输出（Streaming）**：服务端以增量片段持续返回回复内容，界面逐段呈现。
- **整包响应（Non-Streaming）**：服务端一次性返回完整回复内容。

## 需求

### 需求 1：开关

**用户故事：** 作为用户，我希望控制回复的呈现方式，以便在特定网络或服务下获得稳定体验。

#### 验收标准

1. 设置页应提供「流式输出」开关。
2. 系统应默认开启流式输出，与当前行为一致。
3. 当用户切换开关时，系统应持久化选择，并在下次启动时恢复。
4. 当流式输出开启时，系统应逐字增量更新助手气泡。
5. 当流式输出关闭时，系统应在收到完整回复后一次性填充助手气泡。

### 需求 2：请求行为

**用户故事：** 作为用户，我希望开关真实影响请求，以便兼容不支持流式的服务。

#### 验收标准

1. 当流式输出开启时，系统应在请求中声明流式模式。
2. 当流式输出关闭时，系统应在请求中声明非流式模式并解析完整响应。
3. 当关闭流式时，系统应保留既有的取消能力。
4. 当关闭流式时，系统应保留既有的超时与错误提示。

### 需求 3：展示一致性

**用户故事：** 作为用户，我希望两种模式体验一致，以便切换无违和感。

#### 验收标准

1. 当非流式响应到达前，系统应展示等待状态。
2. 当非流式响应到达后，系统应与流式结果渲染方式一致，包含 Markdown 与正则处理。
3. 当请求失败时，两种模式的错误展示应一致。
4. 当开关变化时，系统应只影响后续请求，不改变已展示的消息。
