# 需求文档：消息引用

## 简介

聊天页支持引用某条历史消息：用户长按任意消息选择「引用」，被引用内容以引用块形式展示在输入区与发出的消息中，并在请求时以强调形式告知角色。交互参照 QQ 群聊引用。

## 术语表

- **引用（Quote）**：把某条历史消息作为新消息的附带上下文。
- **引用块（Quote Block）**：消息气泡内展示被引用内容的区域。
- **引用来源（Quote Source）**：被引用的那条消息与其发送者。

## 需求

### 需求 1：发起引用

**用户故事：** 作为用户，我希望引用某条历史消息再回复，以便就特定内容展开讨论。

#### 验收标准

1. 当用户长按消息时，系统应提供「引用」操作。
2. 当用户选择「引用」时，系统应在输入区上方显示引用块，包含被引消息的发送者与文本摘要。
3. 当引用块存在时，系统应提供取消引用的操作。
4. 当用户发送消息时，系统应把引用信息随消息一并保存。
5. 当引用目标消息包含图片或附件时，系统应在引用块中以文本摘要展示，不重复渲染图片。

### 需求 2：引用展示

**用户故事：** 作为用户，我希望在消息里看到引用关系，以便回顾上下文。

#### 验收标准

1. 系统应在含引用的消息气泡内展示引用块，位于正文之上。
2. 引用块应展示被引消息的发送者名称与被引文本，文本超出时截断。
3. 当用户点击引用块时，系统应定位到被引用的原消息。
4. 当被引用的原消息已被删除时，系统应展示占位文案，且不报错。

### 需求 3：引用注入请求

**用户故事：** 作为用户，我希望角色理解我在引用哪条内容，以便回复切题。

#### 验收标准

1. 当用户消息含引用时，系统应在组装请求时把被引内容以明确的强调段落附加到该条用户消息。
2. 系统应在强调段落中标注被引用内容的发送者。
3. 当用户消息不含引用时，系统应保持原有请求结构不变。
4. 系统应在群聊会话中同样适用引用注入。

### 需求 4：数据兼容

**用户故事：** 作为用户，我希望旧消息不受影响，以便升级后继续使用历史记录。

#### 验收标准

1. 系统应把引用信息作为消息的可选字段保存。
2. 当读取到不含引用字段的旧消息时，系统应正常渲染且不报错。
3. 系统应在会话克隆与批量删除等既有操作中保留引用字段。
