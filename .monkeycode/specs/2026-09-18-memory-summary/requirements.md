# 需求文档：记忆总结

## 简介

当一段对话过长时，把历史消息总结为摘要并写入当前角色的世界书，摘要条目按 LLM 生成的关键词触发注入。发送请求时用摘要替代被总结的早期消息，压缩上下文。功能由全局开关控制，阈值可配置，并支持手动触发。

## 术语表

- **记忆总结**：对会话中较早消息生成摘要的过程与结果。
- **总结边界**：最后一次被总结的消息，其后消息不参与下一次总结。
- **摘要条目**：写入角色世界书的记录，含摘要文本与关键词。

## 需求

### 需求 1：开关与阈值

**用户故事：** 作为用户，我希望控制记忆总结是否启用并调整触发长度。

#### 验收标准

1. 系统应提供全局的记忆总结开关，默认关闭。
2. 系统应提供触发阈值配置，默认 40，单位为当前会话消息条数。
3. 系统应把开关与阈值持久化到 `@easychat2_memory_summary`。

### 需求 2：自动触发

#### 验收标准

1. 当开关开启且当前会话消息数超过阈值时，系统应在收到本轮回复后触发一次总结。
2. 当同一会话已记录总结边界时，系统应只总结边界之后、且保留最近若干条以外的消息。
3. 当没有可总结的消息时，系统应跳过本次总结。

### 需求 3：手动触发

**验收标准**

1. 聊天界面应提供「总结记忆」按钮。
2. 当用户点击该按钮时，系统应对当前会话总结边界之后、保留最近若干条以外的消息执行总结。
3. 当开关关闭时，手动触发仍应可用，并在完成后提示。

### 需求 4：总结内容与写入

#### 验收标准

1. 系统应调用 LLM 生成摘要与关键词列表。
2. 系统应把摘要作为新条目写入当前角色世界书，条目名带「记忆总结」与序号。
3. 系统应把 LLM 生成的关键词写入条目的 keys。
4. 系统应把条目设为关键词触发，持续累积多条互不覆盖。
5. 写入的条目应可在角色页世界书中编辑与删除。

### 需求 5：请求压缩

#### 验收标准

1. 当会话存在总结边界时，发送请求应使用摘要替代边界之前的消息。
2. 系统应保留最近若干条未总结消息，使上下文连贯。
3. 当没有总结时，发送请求保持现有行为。

### 需求 6：失败处理

#### 验收标准

1. 当总结失败时，系统应保留原有消息与边界，并在聊天界面提示。
2. 当总结进行中时，系统应避免同一会话重复触发。
