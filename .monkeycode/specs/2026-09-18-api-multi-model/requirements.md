# 需求文档：API 来源多模型与能力标记

## 简介

把「一套 API 配置只对应一个模型」改为「一个来源可对应多个模型」，聊天页可在来源与模型间快速切换；保存来源配置前确认该来源的能力（是否支持思考、是否支持识图），供思考开关与图片上传使用。

## 术语表

- **来源（Source）**：一套接口地址与密钥，即现有的一条 API 配置。
- **模型列表**：来源下可用的多个模型名。
- **当前模型**：来源中被选中的模型，请求实际使用。
- **能力标记**：来源/模型是否支持思考与识图。

## 需求

### 需求 1：来源对应多个模型

**用户故事：** 作为用户，我希望一套接口配置能保存多个模型，方便切换。

#### 验收标准

1. 一条 API 配置应保存模型列表与当前模型。
2. 当读取旧配置（仅有单个 `model`）时，系统应迁移为「模型列表含该模型、当前模型为该模型」。
3. 系统应允许在设置页新增、删除模型，并把某个模型设为当前模型。
4. 当删除的模型是当前模型时，系统应把当前模型回退为列表中的第一个；列表不允许为空。

### 需求 2：聊天页切换模型

#### 验收标准

1. 聊天页顶部栏应提供「模型」切换入口。
2. 打开后应先展示全部来源，再展示所选来源的模型列表。
3. 选择模型后，系统应把该来源的当前模型更新并持久化，后续请求生效。
4. 切换面板应标出当前来源与当前模型。

### 需求 3：保存前能力确认

#### 验收标准

1. 当用户在设置页保存来源配置时，系统应先弹出确认界面。
2. 确认界面应包含「是否支持思考」与「是否支持识图」两个选项。
3. 系统应把两个选项持久化为来源能力标记。
4. 当来源支持识图时，聊天页才允许上传图片；当来源支持思考时，思考开关才可用。

### 需求 4：兼容与安全

#### 验收标准

1. 变更后接口地址与密钥的存储方式不变，仍为 `@easychat2_api_configs`。
2. 密钥仍只在设置页填写，不进入提示词与文档。
3. 旧数据升级后不应丢失原有接口地址、密钥与模型。
