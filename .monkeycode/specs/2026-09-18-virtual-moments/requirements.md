# 需求文档：虚拟朋友圈

## 简介

新增「虚拟朋友圈」功能，可在设置中开关。开启后，用户与角色的对话达到内置阈值（好感最好或最坏、特殊大事、累计 50 次或 100 次对话）时，系统自动生成一条该角色的朋友圈动态。整条时间线为全局展示，用户可对动态点赞、取消点赞、评论与删除；角色会在用户首次评论后对该评论点赞。

## 术语表

- **朋友圈（Moments）**：按时间倒序展示角色动态的时间线。
- **动态（Moment）**：一条角色朋友圈内容，含文本、时间、点赞与评论。
- **好感值（Affinity）**：由本地启发式从对话互动中估算的关系倾向分数，取值区间 `[-100, 100]`。
- **触发阈值（Trigger Threshold）**：产生动态的条件，含好感上下限、特殊大事与累计对话数。
- **特殊大事（Milestone）**：对话中命中的关键事件关键词或长回复事件。

## 需求

### 需求 1：开关与入口

**用户故事：** 作为用户，我希望按需启停并查看朋友圈，以便管理该功能。

#### 验收标准

1. 设置页应提供「虚拟朋友圈」开关。
2. 系统应在开关开启时提供朋友圈入口。
3. 当开关关闭时，系统应不生成新动态，并保留既有动态数据。
4. 系统应持久化开关状态，并在下次启动时恢复。

### 需求 2：好感值与阈值

**用户故事：** 作为用户，我希望动态在关系显著变化时出现，以便感受关系进展。

#### 验收标准

1. 系统应按角色维度维护好感值。
2. 系统应基于对话文本的本地启发式规则更新好感值，不额外调用模型接口。
3. 当好感值首次达到上限阈值时，系统应为该角色生成一条动态。
4. 当好感值首次达到下限阈值时，系统应为该角色生成一条动态。
5. 当对话累计轮次首次达到 50 或 100 时，系统应为该角色生成一条动态。
6. 当命中特殊大事规则时，系统应为该角色生成一条动态。
7. 系统应对同一角色与同一触发条件只生成一次动态。

### 需求 3：时间线展示

**用户故事：** 作为用户，我希望看到动态汇总，以便回顾角色近况。

#### 验收标准

1. 系统应以时间倒序展示全部角色的动态。
2. 每条动态应展示角色名称、头像、文本内容与生成时间。
3. 每条动态应展示点赞数量与评论列表。
4. 当动态已有用户点赞时，系统应展示已点赞状态。
5. 当无任何动态时，系统应展示空状态文案。

### 需求 4：互动

**用户故事：** 作为用户，我希望与动态互动，以便产生往来。

#### 验收标准

1. 当用户点赞时，系统应把用户加入该动态的点赞者列表。
2. 当用户再次点击点赞时，系统应取消点赞。
3. 当用户发表评论时，系统应把评论追加到该动态的评论列表并记录时间。
4. 当用户删除动态时，系统应从时间线移除该动态。
5. 当用户首次评论某条动态后，系统应为该动态追加一条角色对该评论的点赞标记。

### 需求 5：动态内容生成

**用户故事：** 作为用户，我希望动态内容贴合角色与事件，以便阅读自然。

#### 验收标准

1. 系统应基于触发类型与角色设定，从固定模板生成动态文本，不额外调用模型接口。
2. 系统应为不同触发类型使用不同的文本模板。
3. 当角色有群聊或单聊上下文时，系统应保持动态文本与触发事件对应。
