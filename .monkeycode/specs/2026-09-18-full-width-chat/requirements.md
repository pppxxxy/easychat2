# 需求文档：全宽对话

## 简介

新增「全宽对话」开关，开启后助手与用户消息气泡的可用宽度拉伸到最宽，减少因气泡限宽造成的换行。开关关闭时保持当前限宽布局。开关状态持久化，默认关闭。

## 术语表

- **全宽对话（Full Width）**：消息气泡宽度拉伸至聊天区域可用宽度的最大值。
- **限宽布局（Bounded Layout）**：消息气泡按现有最大宽度约束展示的布局。

## 需求

### 需求 1：开关

**用户故事：** 作为用户，我希望消息更宽，以便在长文本和表格场景下更好阅读。

#### 验收标准

1. 设置页应提供「全宽对话」开关。
2. 系统应默认关闭全宽对话，与当前布局一致。
3. 当用户切换开关时，系统应持久化选择，并在下次启动时恢复。
4. 当全宽对话开启时，系统应把用户与助手消息气泡宽度拉伸到聊天区域可用宽度的最大值。
5. 当全宽对话关闭时，系统应恢复现有气泡最大宽度。

### 需求 2：布局一致性

**用户故事：** 作为用户，我希望宽窄切换不破坏其他元素，以便界面保持整洁。

#### 验收标准

1. 当全宽对话开启时，系统应保持左右对齐关系与头像位置不变。
2. 当全宽对话开启时，系统应保持错误气泡与系统报错消息的正常展示。
3. 当全宽对话开启时，系统应保持消息操作行、引用块与配图随气泡宽度自适应。
4. 当全宽对话开启时，系统应保持 Markdown 表格与代码块在气泡内可读，超出宽度时横向滚动。
5. 当切换开关时，系统应无需重启即可生效。
