# H 系设计要点（云构建 / diff / 回滚）

> 做决定的地方。状态：H1–H3 完成（c1009c25）。

## H1 为什么是「手动刷新」而不是自动轮询

任务书没规定轮询方式，实现选**手动刷新**：
- 手机端的长驻 setInterval 涉及生命周期（切面板/后台/卸载）与电量；
- Actions 的 run 从 dispatch 到出现在列表要几秒到几十秒，自动轮询要么等太久要么
  频繁打 GitHub API（secondary rate limit 的典型触发姿势）；
- 「触发 → 过一会儿自己点刷新 → 看日志」的心智负担很低，且每一步都是用户主动的。
代码注释写死了这个取舍；将来真需要自动轮询（比如挂到通知），在面板层加，不动 restApi。

## H1 日志为什么按 zip 处理

GitHub 的 `/actions/runs/{id}/logs` 返回 **zip**（多 job 打包，条目形如
`<job>/1_step.txt`），不是任务书说的「302→文本」。fetch 默认跟随 302（RN 与
undici 都如此）——实现只需处理「拿到 zip bytes → 解包」；解包失败按纯文本兜底
（端点行为若变化也不丢诊断信息）。fflate 已在依赖里（books/docx 在用）。

## H1 工具分层为什么走 options.ci 注入

`tools.js` 有一条架构守卫：**索引层的模块图不得触发 fflate / 网络层 / expo**
（分层炸弹测试）。工具定义层（toolDefs/*）因此全部「零 import」——execute 走
options 注入的 runner（execTools 的先例）。CI 工具沿用：ciTools.js 零重依赖，
`ci.js`（真实桥）在 native.js 注入默认值；token 读取惰性 require storage
（AsyncStorage 不进静态链）。

## H2 为什么 WebView 而不是 RN 逐行渲染 / Monaco

- Monaco：5MB+ assets + 编辑器语义（IntelliSense/多标签），需求（看清改动）用不上；
- RN 逐行 Text：几百行 diff 的渲染压力不小，且没有等宽对齐/横向滚动的天然支持；
- WebView + 静态 HTML：`react-native-webview` **已在依赖**（richHtml/games 在用），
  惰性取（缺失降级为一行提示）；HTML 由纯函数生成（可 Node 直测），
  `javaScriptEnabled={false}` 把脚本面直接关死；XSS 在 `buildDiffHtml` 转义收口
  （测试钉死 `<script>` 不出现）。

## H2 LCS 的 800 行退化线

DP 是 O(n×m) 内存（Int32 表）：800×800 ≈ 640K 格 ≈ 2.5MB，可接受；再大就退化。
退化**不是失败**——「整体删除+整体新增」+ `truncated: true` + HTML 顶部提示
「文件过大，已退化为整体对比」，宁可粗不可假。

## H3 为什么「推送前拉旧内容」而不是推送后

推送成功后远程=本地，旧内容（「这次推送之前远端是什么样」）就再也拿不到了。
所以拉取时机 = **确认之后、提交之前**：
- 确认之前拉 = 用户点取消也白拉（放弃，见 H2 入口②的二期理由）；
- 提交之后拉 = 拿到的是新内容，回滚语义不成立。
拉取在**旁路限额 + 不重试**下进行——它失败不挡推送（reason 记账，回滚时如实说）。

## H3 为什么恢复后不自动弹推送

「恢复 → 自动弹推送确认」会让取消过一次推送的用户在被连环弹窗。恢复只改本地，
推送永远由用户主动发起（按钮就在旁边）；完成提示里写清「现在可以点推送同步」。
这也是「本地路线」的本意：回滚复用既有确认链，不发明新的写远端路径。

## 与既有架构的关系（防跑偏记录）

- 云构建**不注册任何写仓库工具**：dispatch 只是触发 CI，代码内容仍走 C3 的
  Trees API 原子提交（推送路径未被 H 系触碰）。
- 回滚快照是**旁路**（同 pull-manifest / pull-skipped 域纪律）：写失败静默，
  绝不成为推送链路的故障源。
- DiffView 不进入工具定义层（分层炸弹有守卫测试 + workspacePanel 契约断言）。

## 真机验收

1. **云构建**：GitHub 面板工具栏第 7 键 → 填 ci.yml → 触发 → 刷新看到 run →
   点一条看日志（含 job 分节与增删统计无关——日志是纯文本）；
2. **diff 视图**：提交历史点一条 → diff 行级着色（+绿 −红、行号、hunk 头蓝色）；
3. **回滚**：改本地文件 → 推送 → 按钮出现「回滚最近一次推送」→ 恢复 → 文件回到
   旧版 → 点推送 → 确认框列出反向改动；
4. **agent 工具**：「改完这个仓库后触发 CI」→ 模型调 run_remote_build（弹确认）
   → 「读一下构建日志」→ get_build_log 返回状态头 + 日志正文。
