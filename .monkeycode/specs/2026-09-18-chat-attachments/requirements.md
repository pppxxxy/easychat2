# 需求文档：聊天附件与全屏输入

## 简介

聊天输入栏支持上传纯文本类文档与图片，并提供全屏输入。图片仅在来源支持识图时可用。

## 术语表

- **纯文本类文档**：可用 UTF-8 直接读取的文本文件。
- **附件**：随本轮消息一起提交的文档或图片。
- **全屏输入**：放大到全屏的多行输入界面。

## 需求

### 需求 1：上传文档

**用户故事：** 作为用户，我希望把文档内容作为上下文发给模型。

#### 验收标准

1. 输入栏应提供附件入口，可选择文件。
2. 系统应支持读取纯文本类文档：`txt`、`md`、`markdown`、`json`、`csv`、`tsv`、`log`、`xml`、`yaml`、`yml`、`html`、`css`、`js`、`ts`、`jsx`、`tsx`、`py`、`java`、`c`、`cpp`、`h`、`sh`、`ini`、`toml`、`sql`。
3. 当用户选择文本类文档时，系统应读取其内容并在发送时附带。
4. 系统应限制单个文档大小，超出时提示。
5. 当文件无法按文本读取时，系统应提示不支持并跳过。

### 需求 2：上传图片

#### 验收标准

1. 输入栏应支持选择图片。
2. 当来源标记为支持识图时，系统应把图片随消息发送给模型。
3. 当来源不支持识图时，系统应禁用或提示。
4. 输入栏应展示已选附件的名称与缩略并可移除。

### 需求 3：全屏输入

#### 验收标准

1. 输入栏最右侧应提供全屏输入入口。
2. 点击后应打开全屏输入界面，内容与已输入文本一致。
3. 全屏界面右上角应提供关闭按钮，退出后文本保留。
4. 全屏界面应提供发送按钮。

### 需求 4：安全

#### 验收标准

1. 附件内容作为消息上下文，不写入日志中的密钥。
2. 附件不改变既有消息持久化结构中的敏感脱敏规则。
