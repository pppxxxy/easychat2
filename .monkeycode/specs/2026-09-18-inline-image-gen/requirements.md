# 需求文档：对话配图

## 简介

在聊天场景中为助手回复生成配图。默认由用户在助手消息下方手动触发，设置页可开启「自动配图」使每条助手回复自动生成配图。配图展示在对应助手消息下方并持久化。生图服务在设置页配置，新增 NovelAI 适配。

## 术语表

- **配图（Inline Image）**：附着在助手消息下方的生成图片。
- **手动配图（Manual Inline Image）**：用户点击按钮后生成的配图。
- **自动配图（Auto Inline Image）**：助手回复完成后自动生成的配图。
- **NovelAI**：以动漫风格生图著称的服务，使用独立鉴权与响应结构。

## 需求

### 需求 1：配图触发

**用户故事：** 作为用户，我希望按需或自动为回复配图，以便增强阅读体验。

#### 验收标准

1. 系统应在每条助手消息下方提供「生成配图」按钮。
2. 当用户点击该按钮时，系统应以该条助手回复文本为提示词基础发起生图，并把结果展示在该消息下方。
3. 设置页应提供「自动配图」开关。
4. 当自动配图开启时，系统应在每条助手回复完成后自动发起配图生成。
5. 当自动配图关闭时，系统应仅响应手动触发。

### 需求 2：展示与持久化

**用户故事：** 作为用户，我希望配图与消息一起保存，以便回看时仍在。

#### 验收标准

1. 系统应把配图随助手消息一并持久化。
2. 当消息含配图时，系统应在该消息下方展示配图。
3. 当配图生成中时，系统应在该消息下方展示占位加载状态。
4. 当配图生成失败时，系统应在该消息下方展示可读错误与重试操作。
5. 当会话被克隆时，系统应保留配图信息。

### 需求 3：前置校验

**用户故事：** 作为用户，我希望未配置时得到明确提示，以便知道去哪里设置。

#### 验收标准

1. 当生图服务未配置地址或密钥时，系统应提示前往设置配置，且不发起请求。
2. 当同一条消息已有配图时，系统应不重复发起自动配图。
3. 系统应限制同一会话内并发的配图请求数量。

### 需求 4：NovelAI 适配

**用户故事：** 作为用户，我希望使用 NovelAI 生成动漫风格图片，以便获得偏好的画风。

#### 验收标准

1. 系统应内置 NovelAI 生图服务配置。
2. NovelAI 配置应支持填写 API 地址与访问令牌。
3. 系统应支持 NovelAI 的响应形式解析，覆盖 base64 或压缩包返回。
4. 系统应支持 NovelAI 的模型与采样参数映射。
5. 系统应在 NovelAI 与既有五个内置服务之间保持一致调用方式。

### 需求 5：提示词构造

**用户故事：** 作为用户，我希望配图与回复内容相关，以便画面切题。

#### 验收标准

1. 系统应基于助手回复文本构造生图提示词。
2. 当回复文本过长时，系统应按长度上限截断后再构造提示词。
3. 系统应支持在设置中为配图追加固定的风格前缀或后缀。
4. 系统应支持在设置中为配图指定固定尺寸。
