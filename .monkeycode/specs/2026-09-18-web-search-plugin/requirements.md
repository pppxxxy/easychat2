# 需求文档：插件系统与联网搜索插件

## 简介

在全局预设之外引入「插件」概念：插件是带行为能力的全局预设。首个插件为「联网搜索」，用户填写搜索服务 API 密钥并开启后，角色卡可在回答涉及时事的问题时调用联网 API 获取资料并结合回答。

## 术语表

- **插件**：带行为能力的全局预设，可读写外部 API，而不仅注入提示词。
- **联网搜索插件**：本期唯一的插件，通过搜索 API 获取实时资料。
- **触发词**：消息中出现时触发搜索的关键词，如「最新」「今天」「新闻」。
- **背景资料**：搜索结果的摘要片段，注入系统提示词供模型参考。

## 需求

### 需求 1：插件系统

**用户故事：** 作为用户，我希望以插件形式扩展全局能力。

#### 验收标准

1. 系统应内置「联网搜索」插件。
2. 设置页应提供「插件」管理入口，列出插件与启用开关。
3. 插件开关应即时保存并影响后续请求。

### 需求 2：联网搜索插件配置

**用户故事：** 作为用户，我希望填入自己的搜索 API 密钥后即可使用。

#### 验收标准

1. 插件配置应包含 API 密钥输入，支持 SerpAPI、Google Custom Search、Bing 或自定义端点。
2. 密钥输入应以密文形式展示，不完整回显。
3. 用户应能设置单次返回结果数量上限。
4. 当插件开启但未填写密钥时，系统应提示先填写密钥。

### 需求 3：搜索触发与注入

#### 验收标准

1. 当插件开启且最新用户消息命中触发词时，系统应在发送前调用搜索 API。
2. 系统应把搜索结果摘要作为背景资料注入系统提示词。
3. 注入资料应包含标题、来源与链接，并注明获取时间。
4. 未命中触发词时，系统不应发起搜索。
5. 搜索失败或超时时，系统应跳过搜索继续正常对话，不阻塞回复。

### 需求 4：安全与性能

#### 验收标准

1. 搜索 API 密钥不得进入系统提示词、消息文本或错误日志原文。
2. 单次搜索应在 10 秒内超时。
3. 搜索触发频率应有限制，避免逐条消息刷接口。
