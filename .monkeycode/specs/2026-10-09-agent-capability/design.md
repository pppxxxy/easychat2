把差距收敛为四件事（轮次预算 / 截断分级 / 规划与验证引导 / 工作记忆）。
全部增量实现，不推翻任何现有架构。任务清单见同目录 `tasklist.md`。

## 基线核对（2026-10-09，动手前逐条验证，全部属实）
- `loop.js`：`DEFAULT_MAX_TOOL_ROUNDS = 5`；`options.maxRounds` 管道**早已存在**
  但无调用方传值——修复成本比评审暗示的低一个量级（只改默认值 + 补传参）。
- read 工具：offset/limit 分页 + 「继续读取请用 offset=N」续读指针**已存在**，
  评审要的机制文件读取侧不重做，只把同样的语义补齐到其它层（A2）。
- `shell.js` / `mcpTools.js` / `messages.js` 三处截断**只保头**——报错几乎总在尾部。
- `chat.js` 提示词零「计划/验证」引导；子代理 6 轮（不动——隔离刷屏是它的存在理由）。

## 关键设计决策
1. **A1 预算分档**：write 16 / read 10 / 默认 12——写任务跑「改-验」循环天然更长。
   两段式（剩 2 轮预警「开始收束」）比到顶硬截断有效：模型还有机会用文字答，
   而不是被 CAP_NOTICE 截在工具调用中间。
2. **A2 头尾都保 + 指引**：3:1 分配（头 3/4、尾 1/4）；截断句不只标记，还要教
   「怎么拿到更多」——文件 offset 续读 / 命令收窄后重跑。
3. **A0 验证约定不点名工具**：同一段文本会在「只注册了其中一个执行工具」的会话里
   出现，点名另一个 = 承诺一个调不动的能力（与「宁可少说，不能说假话」同款纪律，
   测试钉死）。
4. **A4 键缺失 ≠ 空数组**：缺失 = 没提过（用默认）；空数组 = 明确关闭。parse 保留
   这个区分，合并层（`withDefaultHooks`）只补缺失键；值写坏了当缺失（不因手误关默认）。
5. **A5 会话级 + 切对话清**：它是「这次对话读过什么」的临时状态，不是长期记忆
   （那是 AGENTS.md 的职责）；宿主不注入 readLog 时 read 行为与旧版逐字节一致。
6. **A3 纯回显**：不落盘、无副作用（readOnly，read/write 模式都提供）；
   二期（不在本任务）才接 ChatPanel 进度条展示。

## 明确不做（防止后续重复评估）
1. 工具结果向量检索（工作区侧 token 成本不成比例）；
2. Plan DAG 依赖追踪（A0/A3 轻量引导覆盖 90% 场景）；
3. 上下文老化淘汰（先靠 A2 截断分级）。
