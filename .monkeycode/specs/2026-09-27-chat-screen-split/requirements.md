# 需求文档：ChatScreen 拆分

Feature Name: chat-screen-split
Updated: 2026-09-27

## 简介

`src/ChatScreen.js` 已达 6112 行，成为全仓最大的单文件，阅读与改动成本高、回归面大。本需求要求在**不改变任何用户可见行为**的前提下，按低风险到高风险的顺序把其中可独立的部分外提到 `src/chat/` 目录，形成可持续维护的模块边界。

## 术语表

- **纯搬运**：只移动代码位置、补 import/export，不改变任何逻辑、文案、样式或交互。
- **组件级外提**：把文件内的展示组件（如 `MessageBubble`）搬到独立文件。
- **hook 级外提**：把一组相关状态与回调抽成 `use*` 自定义 hook。
- **源码断言**：测试直接读取某个源文件文本做 `includes` 校验的断言。

## 需求

### 需求 1：行为零变化

**用户故事：** 作为维护者，我希望拆分不改变任何功能，以便拆分本身不引入回归。

当执行任一拆分阶段时，系统应保持现有界面、文案、交互、持久化与竞态处理行为与拆分前完全一致。

### 需求 2：分阶段可独立回滚

**用户故事：** 作为维护者，我希望每个阶段能独立提交与回滚，以便出问题时不必整体回退。

当完成一个拆分阶段时，系统应作为一个独立提交，可在不影响其它阶段的前提下单独回退。

### 需求 3：测试同步更新

**用户故事：** 作为维护者，我希望拆分后测试仍能覆盖原有约束，以便重构不削弱保护。

当代码位置变化导致源码断言测试失效时，系统应同步更新测试读取的路径或符号，使断言继续覆盖同样的约束。

### 需求 4：门禁全绿

**用户故事：** 作为维护者，我希望拆分后项目门禁仍然通过，以便持续集成不被破坏。

当一个拆分阶段完成时，`npm test`、`npm run lint`、`npm run test:coverage` 与 `npx expo export --platform android` 应全部通过。

### 需求 5：路由组件身份不变

**用户故事：** 作为维护者，我希望 `ChatScreen` 的默认导出形态不变，以便导航不会意外重挂载并丢失状态。

当执行拆分时，`src/ChatScreen.js` 的默认导出应保持为 `function ChatScreen()`。

### 需求 6：高风险区域暂不拆分

**用户故事：** 作为维护者，我希望发送主链路与竞态守卫保持原样，以便不触碰已验证的高风险逻辑。

当执行拆分时，会话竞态守卫、发送/群聊/重生成主链路、`recordTurn` 与 affinity 逻辑应保留在 `ChatScreen` 内不动。

## 验收标准

- 拆分后 `ChatScreen.js` 行数显著下降（阶段 A+B 后约 4500 行）。
- 每个阶段提交信息为 `refactor: 从 ChatScreen 抽出 XXX（无行为变化）`。
- 真机手测受影响功能域通过。
