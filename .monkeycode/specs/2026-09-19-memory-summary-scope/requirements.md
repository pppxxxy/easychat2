# 需求文档：记忆总结按会话作用域

## 简介

修复记忆总结「串味」问题。当前记忆总结会写入角色卡的世界书条目，而世界书对该角色的所有会话全局生效；当同一张角色卡在记忆页出现两条及以上记忆（会话）时，写进世界书的总结会跨会话互相污染。改造后：当同一角色存在多条记忆会话时，总结不再写入世界书，而是在各自会话内压缩成上下文随请求发送。

## 术语表

- **记忆**：记忆页中具有非空摘要的会话行。
- **角色记忆条数**：记忆页中 `characterId` 相同且摘要非空的会话数量。
- **上下文压缩**：把会话内已生成的总结合并为一段文本，作为请求上下文注入，而非写入世界书。

## 需求

### 需求 1：按会话作用域改写总结落点

**用户故事：** 作为用户，我希望同一角色的多个会话的记忆互不串味。

#### 验收标准

1. 当某角色在记忆页的记忆条数 ≥ 2 时，该角色的记忆总结不应再新增世界书条目。
2. 当记忆条数 < 2 时，系统应保持既有行为：总结写入角色世界书的「记忆总结」条目。
3. 系统应已存在的「记忆总结」世界书条目保留，不自动删除或迁移。
4. 总结边界（`summarizedUpTo`）应按会话更新，与是否写入世界书无关。

### 需求 2：压缩上下文随请求发送

#### 验收标准

1. 当角色记忆条数 ≥ 2 时，系统应把该会话已生成的总结合并为一段上下文，随每次请求发送。
2. 该上下文应通过既有的 `[记忆摘要]` 注入点发送，不依赖世界书条目。
3. 当会话尚无总结时，系统应不注入摘要上下文。
4. 当角色记忆条数 < 2 时，摘要来源应保持既有世界书读取逻辑。

### 需求 3：总结存储与读取

#### 验收标准

1. 系统应把不写入世界书的总结按会话持久化保存，键名或字段不与世界书混淆。
2. 读取摘要上下文时，应能同时兼容：既有世界书条目（旧数据）与会话内总结（新数据）。
3. 当同一会话重复总结时，应按顺序追加或替换，避免重复注入同一段总结。
