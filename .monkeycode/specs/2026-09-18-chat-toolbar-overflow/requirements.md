# 需求文档：聊天页顶部折叠与聊天设置

## 简介

聊天页顶部按钮数量过多，挤压角色头像与名称。将「公告 / 模型 / 思考 / 定位 / 搜索 / 总结」等次要入口折叠进单个「⋯」菜单，为角色头像与名称腾出空间；同时新增「聊天设置」弹窗，内含系统设置入口与「编辑角色」入口。

## 术语表

- **更多菜单（More Menu）**：顶部栏「⋯」按钮展开的菜单，收纳次要功能入口。
- **聊天设置（Chat Settings）**：聊天页内打开的弹窗，聚合与当前角色相关的设置入口。

## 需求

### 需求 1：顶部折叠

**用户故事：** 作为用户，我希望顶部更简洁，以便角色头像与名称有足够位置。

#### 验收标准

1. 聊天页顶部栏应保留角色头像、角色名称、播报开关与「新建」按钮。
2. 聊天页顶部栏应提供单个「⋯」入口，展开后包含「公告」「模型」「思考」「定位」「搜索」「总结」。
3. 当用户点选菜单项时，系统应执行与折叠前一致的操作。
4. 当菜单项不可用时，系统应保持其在折叠前的禁用表现。
5. 当顶部栏展开菜单时，系统应不改变消息列表滚动位置。

### 需求 2：聊天设置弹窗

**用户故事：** 作为用户，我希望在聊天页直接进入设置与角色编辑，以便减少页面跳转。

#### 验收标准

1. 「⋯」菜单应包含「设置」入口，点击后弹出聊天设置弹窗。
2. 聊天设置弹窗应包含「系统设置」入口，点击后进入设置页。
3. 聊天设置弹窗应包含「编辑角色」入口，点击后在聊天页就地弹出角色编辑弹窗。
4. 角色编辑弹窗应支持编辑当前角色的名称、头像、背景、人设、角色描述、性格、标签、世界书、正则与预设。
5. 当角色为群聊时，系统应隐藏「编辑角色」入口并给出说明。
6. 当用户在角色编辑弹窗保存后，系统应更新当前角色并刷新聊天页展示的名称与头像。
7. 当用户在角色编辑弹窗中编辑世界书与正则时，系统应支持逐条增删与编辑。
8. 当保存失败时，系统应提示并保留用户已填内容。

### 需求 3：状态一致性

**用户故事：** 作为用户，我希望折叠与弹窗不影响既有行为，以便升级后使用如常。

#### 验收标准

1. 折叠后「定位」的无消息禁用、「搜索」的开关态与「总结」的进行中态应保持不变。
2. 角色编辑保存失败时，系统应提示且保持原内容。
3. 播报开关在折叠后仍常驻可见。
