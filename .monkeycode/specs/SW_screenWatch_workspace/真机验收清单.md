## 1. M1 保命：两个「真机直接坏掉」的 bug

### 1.1 bug③ 点输入框后「小窗以外全部卡死」

> 根因：清 `FLAG_NOT_FOCUSABLE` 会连带取消系统**隐含**的 `FLAG_NOT_TOUCH_MODAL`，
> 窗口瞬间变 touch-modal，吞掉窗外所有触摸。修法是聚焦时显式补回 `NOT_TOUCH_MODAL`。

- [ ] **M1.1.1** 开启悬浮窗 → 展开面板 → **点输入框**（键盘弹出）。
- [ ] **M1.1.2** 此时**不收起悬浮窗**，直接滑动悬浮窗**外面**的桌面/其他 app 列表。
      **期望：正常滑动**。（修复前：完全没反应，像死机）
- [ ] **M1.1.3** 同样状态下，点悬浮窗**外面**的其他 app 图标。
      **期望：能点开**。
- [ ] **M1.1.4** 点输入框**失焦**（点悬浮窗内空白处）→ 再滑动窗外。**期望：仍正常**。
- [ ] **M1.1.5** 反复「聚焦 → 失焦」10 次，每次窗外都能滑。**期望：无一次卡死**。

### 1.2 bug④ 卡死 → 收起 → 悬浮窗消失 → app 呈重启状

> 根因：焦点持有 + IME 绑在 overlay 窗口 + 从 Service `startActivity` 拉起 RN 主 Activity
> → 主线程被堵 → 输入事件 5 秒未分发 → ANR → 杀进程 → 前台服务陪葬。
> 修法：物理移除 `openAppForTalk()` 与 OverlayService 内全部 `startActivity`。

- [ ] **M1.2.1** 「说话」按钮**不再跳回 app**（点它只在窗内开始录音，按钮文案变「停止」）。
- [ ] **M1.2.2** 点「说话」→ 再点「停止」→ **app 没有被拉到前台**。
- [ ] **M1.2.3** 连续做 20 次「说话/停止」或「截屏」，**全程无 ANR 弹窗、无进程重启**
      （判据：悬浮窗始终在，app 没有被冷启动）。
- [ ] **M1.2.4** 连续 20 次操作期间，`adb logcat` 无 `ANR in com.pppxxxy.easychat2`
      （不会 adb 就跳过，靠 0.2 的 ANR 弹窗判定）。
- [ ] **M1.2.5** 收起再展开悬浮窗 10 次，**悬浮窗不消失**、内容正常。

### 1.3 M1.3 授权独立化（app 在后台也能重授权）

> 根因：旧实现用 `currentActivity.startActivityForResult`，授权绑死 RN 主 Activity，
> app 不在前台时走不了。修法：独立透明 Activity + 进程级结果投递。

- [ ] **M1.3.1** 锁屏 → 解锁 → 点「截屏」。**期望**：出现「重新授权截屏」**通知**。
- [ ] **M1.3.2** **在 app 处于后台时**点该通知 → **能弹出系统投屏授权框** → 确认后
      再点「截屏」**能截到**。（这是 M1.3 的核心验收项）
- [ ] **M1.3.3** 授权 Activity 出现时**不闪白屏/黑屏**（透明主题生效）。
- [ ] **M1.3.4** 授权完成后按「最近任务」，**没有多出一张空白应用卡片**（独立 taskAffinity 生效）。
- [ ] **M1.3.5** 用户**拒绝**投屏授权 → 悬浮窗**不闪退**，气泡/状态给出可读提示。
- [ ] **M1.3.6** 「开启 → 关闭 → 再开启」反复 3 轮，**不闪退**（这是历史上连环闪退的路径）。
- [ ] **M1.3.7** 荣耀真机：app 在后台时点通知，授权 Activity 是否被系统拦截？
      **期望**：能起来（本应用持有 `SYSTEM_ALERT_WINDOW`，是后台起 Activity 的豁免条件之一）。
      若被拦，记录现象——这是需要单独处置的 ROM 行为。

## 2. M2 大脑搬家：悬浮窗不依赖 JS 存活

### 2.1 核心：杀进程后悬浮窗仍能聊天

> 架构总纲：悬浮窗自己会听、会想、会说；RN 只在 app 打开时提供配置与历史。
> 前提：**必须先在 app 里打开过「看屏幕」页**（写入配置快照），否则原生无凭据可用，
> 会回退 JS 管线——那是**预期行为**，不是 bug。

- [ ] **M2.1.1** 先在 app 内打开「扩展 → 世界 → 看屏幕」一次（写入配置快照），然后开悬浮窗。
- [ ] **M2.1.2** 回桌面（app 到后台）→ 在悬浮窗输入框发一句「你好」。**期望：有回复**。
- [ ] **M2.1.3** `adb shell am kill com.pppxxxy.easychat2`（或开发者选项「不保留活动」+
      切走再切回）→ 悬浮窗**仍在** → 发一句。**期望：仍有回复**（这是 M2 的核心验收项）。
      > 注：`am kill` 会杀整个进程，同进程的前台服务可能一起没。若悬浮窗随进程消失，
      > 那说明 ROM 直接杀了进程——记录现象；用「不保留活动」那条路径更能验证
      > 「JS 实例销毁但原生服务还在」。
- [ ] **M2.1.4** 打开「不保留活动」后：切到别的 app 再回悬浮窗，**聊天仍正常**。
- [ ] **M2.1.5** 热重载/重启 app 后，悬浮窗**没有被关掉**（`invalidate()` 不再停服务——
      这是 M2 与旧架构的**有意冲突点**，旧行为是「JS 死了就停服务」）。

### 2.2 三类失败必须各有正确气泡

- [ ] **M2.2.1** **断网**（开飞行模式）→ 发一句。**期望**：气泡显示可读的失败原因
      （不是永远转圈、不是空白）。
- [ ] **M2.2.2** **错 key**（设置里把 apiKey 改错）→ 发一句。**期望**：气泡提示
      「请求失败（HTTP 401），请检查密钥或模型名」这类**可处置**的信息。
- [ ] **M2.2.3** **429/5xx**（若不好构造，可用一个错误的 baseUrl 观察）→
      **期望**：按 fallback 链换模型重试，最终失败时给可读提示。
- [ ] **M2.2.4** **非 openai 协议**（把配置协议改成 anthropic）→ 发一句。
      **期望**：气泡明确说「当前协议需在 App 内使用」，**不静默降级**。

### 2.3 流式与配置快照

- [ ] **M2.3.1** 回复是**逐字出现**的（流式），不是等全部生成完才一次性冒出。
- [ ] **M2.3.2** 在 app 里**改 API 配置**（换模型）→ 回桌面 → 悬浮窗发一句。

### 2.4 M2.5 会话互通

## 5. 专项：荣耀 ROM 后台冻结（本套改动的首要目标）

> FIX-4 已实证：国产 ROM 冻结后台进程时**整个主线程暂停**，采集兜底与超时全部失灵。
> M1–M4 把大脑搬到原生、把重活搬出主线程，但**进程级冻结**是系统行为、代码改不掉。
> 这一节就是判定「改完之后到底还剩多少」。

- [ ] **5.1** 设置 → 电池 → 本应用设为「不受限制 / 允许后台活动」。
- [ ] **5.2** 设置 → 应用启动管理 → 本应用**手动管理**：允许自启动、关联启动、后台活动。
- [ ] **5.3** 配置好以上后，回桌面用悬浮窗连发 3 句。**期望**：都有回复、不「一直等」。
- [ ] **5.4** 锁屏放置 10 分钟 → 解锁 → 点「截屏」。**期望**：能截到
      （若失败，应出现「重新授权截屏」通知，而不是静默卡住）。
- [ ] **5.5** 锁屏放置 10 分钟 → 解锁 → 悬浮窗发一句。**期望**：有回复。
- [ ] **5.6** 若出现「点了没反应/一直等」：立刻打开诊断日志，**记录最后一个打点 stage**。
      这是定位 ROM 冻结点的唯一线索，请连同 `M4.4` 的日志一起回报。

## 6. 已知未核实项（预期可能失败，失败请回报而非视为回归）

以下都是**本机无法验证**的原生行为，实现时已如实标注，真机可能不通过：

| # | 项 | 预期风险 | 失败时的现象 |
|---|---|---|---|
| 6.1 | AudioRecord 16kHz 直采 | 部分设备不支持 16kHz 直采，需 44.1k 重采样 | 点「说话」立刻提示不可用，或录出的音频识别不出 |
| 6.2 | 系统 SpeechRecognizer | 国产 ROM 可用性差（无识别服务/必须联网/直接 ERROR_CLIENT） | 退回系统识别时报「语音识别不可用」 |
| 6.3 | 系统中文 TTS 引擎 | 部分 ROM 未预装中文引擎 | 气泡提示「系统语音播报不可用」 |
| 6.4 | 通知栏 action 呈现 | 部分 ROM 折叠动作或限制动作数量 | 通知里看不到三个按钮 |
| 6.5 | 后台起授权 Activity | Android 10+ 限制后台启动 Activity | M1.3.2 点通知后授权框不出现 |
| 6.6 | `am kill` 后悬浮窗存活 | 同进程下杀进程会连服务一起杀 | M2.1.3 悬浮窗随进程消失 |

## 7. 回报模板

失败项请按这个格式回报（编号 + 现象 + 日志）：

```
编号：M2.2.2
现象：改错 key 后发消息，气泡一直显示「…」不变，等 30 秒也没有结果
诊断日志：最后一条是 brain-request model=xxx vision=false，没有 brain-fail
```
